# Grok Memory 2026-07-27l — 并行 gate 下 head/base 前进导致重审浪费：问题与成熟方案

> 性质：设计备忘（提案向）。**非** gate verdict、**非** 已封存 assignment。  
> 会话：Grok 4.5 (high effort) / Ubuntu `hctl-grok`。  
> 触发：用户观察——多 review/gate 并行时，comment 或 PR/memo 合入使 head（或 base）前进 ⇒ 现架构下 exact revision 失效 ⇒ 全量 re-gate，token/时间浪费。  
> 相关定案：D-04 / D-34 / D-37（严格 base）/ D-40 / D-41；实证摩擦：27o F4、PR #38 多次 re-nail。

---

## 1. 问题陈述

P1 法律把 **freshness 粒度** 钉在整棵 revision OID 上：

| 规则 | 效果 |
|---|---|
| D-04 / D-40 | verdict 钉 exact `{base, head}` |
| D-34 | gate/merge claim：base **或** head 任一前进 ⇒ claim **stale**，须显式 re-claim |
| D-41 | required quorum = exact revision + COMPLETE + APPROVE + scope 覆盖 |

并行场景下常见前进源：

1. **base 前进**：memo lane 微 PR 合 main（「先合 memo 后落 verdict」硬门放大此摩擦，D-40/27o F4）。  
2. **head 前进**：作者小修、rebase、为评论改一行、无关 path push。  

结果：旧 APPROVE 对 **merge 前快照** 不计数——**安全正确**，但大量重审针对的是 **非语义前进**（tree 未变、或 path 与本 gate 评审面不相交）。

这不是实现 bug，是 **「OID 字面全等 = 唯一 freshness」** 的定价。

---

## 2. 勿混淆的两层

| 层 | 现状 | 松弛应落在 |
|---|---|---|
| **claim 阻尼** | base-only 已标 `environment_reset`、streak 清（D-34）——承认「不是 claimant 抖动」 | 勿靠「head 动了 claim 仍不 stale」偷懒（破坏 fencing，D-35） |
| **verdict / quorum 计票** | 仍要求 exact `{base,head}` 才进 green | **在此**引入可机械证明的继承谓词 |

正确形状：

```text
claim 仍可 stale（或 re-claim 很轻）
旧 verdict 进入「候选继承」集合
derive 用 tree / path / freeze 规则决定是否计入 green
```

---

## 3. 成熟方案谱系（轻 → 重）

### 3.1 流程层（零协议改动，立刻可用）

- **静默窗口**：required gate 开跑后禁 memo 合 main、禁无关 PR 进 main。  
- **memo 后置 / 批量**：减少 base 抖动次数。  
- **串行 required / 并行仅 advisory**。  
- **作者 freeze tip**：评审中不 push；只认冻结 head。  

级④ 纪律，dogfood 可写排班/coordinator 说明；**不当内核法律**。

### 3.2 内容等价携带（tree-equivalent carry）— 推荐的第一刀内核松弛

旧 verdict 在新 revision 上可继承，当且仅当 **可机械证明**，例如：

```text
tree(old_head) == tree(new_head)          # 同内容（空 rebase / 只改 message）
  且 is-ancestor(old_base, new_base)      # base 只前进、无回卷
```

或更严：同 tree 且 `diff old_base..new_base` 与本 PR 合入路径的交为空（视产品选择）。

| 优点 | 风险 / 条件 |
|---|---|
| 直接消灭「memo 推 main、代码树未变」类假重审 | 须 batch plumbing 比 tree；schema_version / 显式 amends D-04「字面全等」 |
| 与 D-41 收敛同向 | 语料要拆 base-advance：tree 同 vs tree 异 |

业界：Gerrit rebase 后 **copy votes**（可配置条件）；CI 对 identical-tree rebase 常特殊处理。

### 3.3 路径 / 评审面作用域 freshness（path-disjoint carry）

assignment 或 gate 声明 `review_surface`（path glob 或等价）：

```text
changed = paths(old_head..new_head) ∪ (paths(old_base..new_base) ∩ merge-relevant)
if changed ∩ review_surface == ∅:
    旧 APPROVE 仍计票（标 path-disjoint / environment carry）
else:
    仅对 intersection 要求 delta / fix_verification（D-41 已有形状）
```

| 优点 | 风险 |
|---|---|
| 真并行：他席 memo、无关文件不再误伤 | surface 错 = 漏审；需 doctor 硬检非空/不自欺 |
| 与 composite scope 天然拼 | D-41 曾故意不做 surface map（E3 保守）——打开要裁定 |

业界：CODEOWNERS、Gerrit file list、monorepo affected targets。

**这是「严格 base 松弛」（D-37：P3 前禁旋钮）的正确打开方式**——不是放宽 base 字符串，而是放宽 **「何谓影响本 gate 的 diff」**。

### 3.4 冻结集成点 / 两阶段评审

```text
阶段 A  开放 head：advisory、对话、修代码（票不进 required quorum 或进但不阻塞 merge）
阶段 B  freeze tip T：required 只钉 T；freeze 后 push = 显式解冻 + 重开
```

或 `refs/hctl/freeze/<assignment>` 与 live PR head 分离。

业界：release train、draft→ready、topic freeze。

### 3.5 已有但未用满：D-41 composite

第二轮 **协议已允许** 只做 `fix_verification` + `delta`，不必 full。  
浪费常来自：claim 先 stale 导致整轮心智重来，或 agent 默认又跑 full。

**便宜 UX（几乎不改法律）**：

- `hctl status` / verdict 辅助：若 `is-ancestor(old_head, new_head)`，next 自描述为  
  `re-claim + delta from <old_tree|old_head>`，并附 `git diff --stat`。  
- 禁止文案暗示「任何 OID 变 ⇒ 必须 full」。

不减少 re-claim 次数，但可砍 **token**。

## 4. 明确不建议

| 做法 | 理由 |
|---|---|
| 纯时间窗（「N 小时内 base 动了也算」） | 不可重放，反 D-02 |
| 默认 latest head 自动继承所有 APPROVE | 拆掉 exact revision 安全核 |
| 靠 LLM「看起来差不多」 | 级④ 灾难 |
| head 动了 claim 仍不 stale | 破坏 fencing（D-35） |

---

## 5. 建议路线（供排班，非本 memo 终裁）

| 阶段 | 内容 | 主要节省 |
|---|---|---|
| **现在** | 静默窗口 + status 引导 delta；memo 与 required gate 时序拆开 | 流程 |
| **P1.1 / P2 小** | **tree-equivalent carry** + derive/quorum 继承谓词 + 语料两支 | 假重审大头 |
| **P2** | `review_surface` + path-disjoint carry；与 D-41 surface 对齐 | 真并行 |
| **P3** | freeze ref / 两阶段；再议严格 base 旋钮（D-37 已留口） | 大型 adopters |

**最小可裁定提案（若用户开工 assignment）**：  
只做 tree-equivalent carry + status 自描述 delta；单独立项；不动 HANDOFF、不动「任意 base 松弛」大旋钮。  
须 amends 表：D-04 / D-40（计票例外）/ 可能 D-41（继承后 scope 语义）；D-34 claim 阻尼可不动。

---

## 6. 一句话

> 成熟解不是取消 exact revision，而是：  
> **默认仍钉 OID；在可机械证明「评审面无新语义」时，允许旧 APPROVE 继承**  
> （tree 等价 ⊂ path 作用域 ⊂ freeze 点）。

零件已有：delta / fix_verification、environment_reset 叙事。  
缺的是 **quorum 侧继承谓词** 与（下一步）**surface 声明**。
