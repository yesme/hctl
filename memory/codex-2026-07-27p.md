## 1. `codex-pr72#P1-01` — object failure 可扩大认账集并静默 INVALID

### 1.1 根因

`internal/derive/cutover.go:63-67,96-111` 把历史 enforcement 压成 `bool`。
`batch.Read(commit:.hctl/seats.toml)` 的任何错误、非 blob、TOML decode 错误都被
统一当成 `false`，且缓存进 tree verdict。代码与 METHOD 声称这种误判“只会收紧”，
但 acknowledged set 的定义是 `cutover + ancestors`；把一个真实 active commit 判成
non-active 会把 cutover 向 tip 移动，反而把更晚 commit 纳入认账集。

### 1.2 最小反例 A：边界被扩大

用真实 Git loose objects 建三段 first-parent 历史，三个 seats blob/tree 均不同：

```text
root-first: bootstrap(root) → active(mid) → active(tip)
intact:     cutover=mid; acknowledged={mid,root}; tip excluded
```

只删除 `mid:.hctl/seats.toml` 的 blob，commit/tree 与 tip config 均仍可读。T_final
不是报 `INVALID_CUTOVER`，而是：

```text
problem=nil
cutover=tip
acknowledged={tip,mid,root}
```

即对象完整性失败把原本应在边界外的 tip 纳入 warning 区。

### 1.3 最小反例 B：多翻转被静默

```text
root-first: active(root) → bootstrap(mid) → active(tip)
intact:     INVALID_CUTOVER
```

只删除 root active seats blob 后，当前实现把 root 当 non-active，返回
`problem=nil + cutover=tip`。因此同一错误折叠还能直接消掉冻结第 5 条要求的
multiple-cutover fail-closed。

作者现有 `TestDetectCutoverShapes` 把一份 `garbage` 祖先作为合法 non-active happy
case，没有覆盖“不可判定导致边界扩大”或“不可判定藏掉旧 active”两支；case #30 也
只生成对象完整的历史。

### 1.4 Closure contract

1. enforcement history 必须至少为 `active / proven-non-active / unknown(error)` 三态；
   真正 path 不存在可按已定义的 non-active 处理，但 object resolution、对象类型与
   decode 不可判定不得静默压成 `false`。
2. unknown/error 必须产生 fail-closed error；不得返回可用于
   `cutover.covers` 的 boundary。
3. 固化上述两个真实-object mutation；恢复 bool/error swallowing 时测试必红。
4. 保留 bootstrap-only、genesis-active、正常单翻转、显式 missing-path 等相邻 happy
   路径，证明修复没有把“尚无 seats 文件”误杀成扩大认账。

## 2. `codex-pr72#P1-02` — tree reuse 把 post-cutover merge 认到旧 OID

### 2.1 根因

`internal/derive/merge_history.go:92-115` 用 candidate `headTree` 扫描**整条**
`MainHistory`，第一个同 tree 且有 parent 的 commit 就被当作 integration commit。
该选择没有绑定 assignment revision/base、candidate chronology 或实际 reachable
merge。随后 `markMergeDebt` 只看这个误选 OID 是否在 cutover set。

在 cutover 以前，tree 误配至少仍产生全局 error；本 PR 把误选到边界内的 OID 降成
warning，故旧 heuristic 被新 cutover 语义放大成 false-open。

### 2.2 最小反例

构造：

```text
main: bootstrap root
   → active cutover, tree=C
   → active tip,     tree=T

side candidate after active tip: parent=active tip, tree=C
post-cutover main integration:   parents=(active tip, side candidate), tree=T
```

candidate 已真实 reachable 于一个 post-cutover two-parent merge，正确分类应为
`UNJUDGEABLE_MERGE error`。当前扫描先跳过 tree=T 的新 merge/tip，随后命中旧
`cutover(tree=C)`，实际得到：

```text
MergedCommit = <cutover OID>
AuditDebt    = ACKNOWLEDGED_BOOTSTRAP_HISTORY
problem      = warning (... UNRECORDED_MERGE ...)
WriteGuard   = allowed
```

这同时违反冻结第 3 条“cutover 后 unjudgeable 仍 error”和 gate lens 的“误认账/
tree 复用逃逸”。case #30 的 post-cutover branch 使用唯一新 tree，因此现有 corpus
无法杀死该实现。

### 2.3 Closure contract

1. unrecorded integration 的定位必须绑定候选 revision 的时间/祖先边界；tree equality
   只能是必要证据，不能让 candidate base 以前的 first-parent OID 代替实际 integration。
2. candidate 已 reachable、但 cutover 后找不到可判定 squash integration 时，必须走
   post-cutover `UNJUDGEABLE_MERGE error`，不得回落到旧 tree match。
3. 固化上述 distinct-active-tree + side-parent fixture；删掉 chronology/ancestry guard
   时测试必红。
4. 保留真实 pre-cutover unrecorded squash 的 happy acknowledgment，证明不是简单禁用
   tree matching。

## 3. `codex-pr72#P1-03` — 认账 debt class 超出冻结授权

codex-27k §3.3 第 2 条只授权：

```text
cutover commit 及其祖先上的既有 UNRECORDED_MERGE
  → ACKNOWLEDGED_BOOTSTRAP_HISTORY warning
```

第 3 条则明确 post-cutover 的
`unrecorded / invalid / unjudgeable` 全部保持 error。该冻结面没有授权把历史
`INVALID_RECEIPT`（已有但错误/不可信的 receipt）或 `UNJUDGEABLE_MERGE`
（非 squash/无法判定）等同于“bootstrap 时没有 receipt”。

但 `merge_history.go:287-296` 对任意 `code` 只要 `cutover.covers(mergedOID)` 就统一
降级。直接以 covered OID 分别注入两类 reachable call，实际均为：

```text
INVALID_RECEIPT   → ACKNOWLEDGED_BOOTSTRAP_HISTORY warning; WriteGuard allowed
UNJUDGEABLE_MERGE → ACKNOWLEDGED_BOOTSTRAP_HISTORY warning; WriteGuard allowed
```

因此 malformed/tampered receipt 或 non-squash activation 也会获得本 assignment
没有授予的 bootstrap 豁免。METHOD/D-38 在本 PR 中把三类一起写进 prose，是实现
顺手扩大后的描述，不能反向修改冻结 assignment。

### Closure contract

1. acknowledgment 必须有显式 debt-code allowlist；本轮只含
   `UNRECORDED_MERGE`。`INVALID_RECEIPT`、`UNJUDGEABLE_MERGE` 在 boundary 内外均
   保持原 code + error。
2. 表驱动覆盖三类 debt × inside/outside/unplaced；特别固定 cutover commit 上
   unrecorded squash 可 warning、invalid receipt/non-squash 仍 error。
3. DECISIONS/METHOD 与冻结六条重新对齐，不以 candidate prose 自扩 authority。
4. 去掉 allowlist 或把三类共降级时，mutation test 必红。
