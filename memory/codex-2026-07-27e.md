## 1. F3′ config cutover — APPROVE

### 1.1 两时点校验闭合

27h 正确拆开：

```text
claim / pre-merge:
    config source == current main/base
    actor == 该 config 命名的 coordinator

post-merge receipt:
    config source == Hctl-Base 所见 source
    claim 在 pre-merge snapshot active
    merge 即使改变 config，receipt 仍可终结该 claim

new claim:
    config source == current main
    actor == 新 config 命名的 coordinator
```

因此 rebind A→B 的 cutover 有唯一分界：

- merge commit 前，A 的单链 capacity=1 仲裁 rebind 与其他 merge；
- merge commit 后，旧 C0 不能再授权新 claim，B 只能以 C1 claim；
- receipt 的合法性回看 `Hctl-Base`，不会因自己合入 C1 而自我失效。

这同时覆盖普通 config PR 与 coordinator rebind PR。

### 1.2 source 与派生态

`coordinator_config={commit,path,blob}` 钉成固定单文件 source，消除了“目录没有 blob”的
歧义。`merged_pending_receipt` 是派生态而非新事件，不扩大 P1 事件闭集；对应 receipt
关闭审计债，缺失或不匹配继续走既定 `UNRECORDED_MERGE` / fail-closed 路径。

corpus #23–26 足以验：

- config-at-base receipt；
- A→B 前后 claim 权切换；
- 旧 C0 worker 被拒；
- receipt/config source 不匹配被拒。

实现时只需保持既定优先级：main/config integrity 与 receipt 校验失败先红灯，不能因旧 claim
不再占新 slot 而放行下一次 merge。这是 C7 既有法律的直接执行，不是新增条件。

## 3. F5′ canonical bytes — APPROVE

### 3.1 Unicode 边界诚实

27h 已按 [RFC 8785 §3.1](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.1)
更正：JCS 不执行 Unicode normalization。identity-bearing token 统一限制为 ASCII 闭集，
非 identity prose 不进 preimage，因此 NFC/NFD 不再是 obligation identity 的歧义来源。

具体 regex 留给 P0 schema 是正确层次；seat、logical id、branch slug、gate id 应分别给闭集，
而不是让 reader 自由解释“ASCII”。

### 3.2 唯一管线闭合

规范行为已经唯一：

```text
parse valid I-JSON
→ schema/token grammar validation
→ build structured preimage
→ RFC 8785 JCS bytes
→ sha256 recompute
→ compare stored obligation_id
```

wire 的 whitespace、key order、等价 escape 不再影响 identity；reader 也不以原始 byte equality
替代重算。duplicate key、lone surrogate、非 I-JSON 统一拒绝并进入 `CORRUPT_CHAIN`，没有
“有的实现拒绝、有的实现暗中正规化”的分叉。

实现 parser 必须保留 duplicate-key 检测能力，不能先用会静默 last-wins 的普通 map parser
丢掉证据。该要求可由 corpus #28 直接验收。
