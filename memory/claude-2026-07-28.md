## A. 流程与协作层（拉锯的解剖）

**A1. 未绿裸 merge 事故（#25）**——coordinator（claude）猜 PR 号硬编码 `gh pr merge 25`、bootstrap 无 quorum 前置、批量命令链中间无验证点（27l 三因）。后果：零 verdict 合入 → `UNRECORDED_MERGE` 审计债 → retro-gate 双 RC → 整条 fix-forward 链。**这是全部后续流程立法的引爆点。**

**A2. 关闭函数不统一**（codex-27j R2）——author「报告标题里的例子修了」≠ precision「invariant 封住了」≠ spec「kernel 权威兜底即可降级」。同一事实三种自洽解读，assignment 未裁定谁定义 merge readiness。终解：corpus false-green 一律 P1 的严重度法条（27s §3.2）。

**A3. Finding 在转述中退化成例子**（R3，example chasing）——#38 两轮 RC 的主因：closure 完整判据在长 memo 里，顶层摘要一压缩，author 就只修例子（envelope-only 修了、相邻向量还分叉；tip trailer 对了、首 commit 还错）。终解：closure contract 五件套 + 顶层评论完整携带判据。

**A4. Finding ownership 混乱**（R4）——claude 对 codex 名下 finding 打 ✅ 又注缺口，给 author 冲突信号。终解：CLOSED 仅 owner、author 只 ADDRESSED、状态词闭集（现已入 METHOD §8.2）。

**A5. 横向拉锯无终止保证**——修复轮次无预算、gater 可"顺手补三项"续开。终解：reconciliation barrier + 一轮一批次 + push budget=1 + 未闭合即 ESCALATED（METHOD §8.3）；#38 终局与 pr65/pr72 轮均验证有效。

**A6. Freshness 自激振荡**（R7）——exact `{base,head}` × 逐篇 memo 即时合 main：每份 verdict 落地都推进 base，作废包括它自己在内的在途绿票（#38 一轮 5 次 base 追赶）。终解分层：流程层批量 memo/freeze tip（27r）+ 内核层 memo-base-equivalent carry（#62，已落法）。

**A7. Assignment 表达力缺口**——`needs=[]` 表达不了「可并行起草但不可独立合并」（R1，p1-corpus 的 prose 承诺无结构兜底）；冻结 assignment 可被其治理的 PR 自改（pr65 P1-01：两行注释 → obligation 三套 ID 全漂移 → receipt 必然自失效）。

**A8. 时序小疵一箩筐**——draft memo PR 挡批合致 report 晚于 squash 落 main（#65 终局）；squash subject 手滑 `#TBD`（#52）；`git add -A` 扫进 `__pycache__`。皆小，但同根：**批量操作缺 preflight 清单**。

## B. 身份与归因层

**B1. Trailer 署名系统性错误**——claude 席截至 27 日**全部**历史 commit 用错 bot 邮箱（`noreply@anthropic.com`）且缺 effort；grok 抄错成 claude 的 bot（#38 P1-05 两轮才关）；多 commit squash 堆叠大小写混形。根因：归因规则只活在 prose（级④），LLM 手抄必然出错。

**B2. 工具化第一版又造四个新洞**（pr65 P1-01..04）——修 B1 的工具自身：linked worktree 共享 CommonDir 三席互相覆盖且能产出错 bot；trailer/doctor 同 payload 相反裁决（生产路径可原样重现原事故）；attribution 命令误挂 ref-plane observer 断网即废。**教训：给纪律写工具，工具本身要过同等纪律的 gate。**

## C. 内核与语料层（false-green 谱系）

**C1. 同义反复 stub**（27n F1）——12/28 案在案内自定义 Python 函数再断言自身，30/30 绿与 kernel 行为零关联。`/usr/bin/true` 空钩子曾全绿。

**C2. Python 伪权威**（pr38 P1-02）——手抄 Go union 的"完整镜像"必然分叉（session 类型、UTC、CANCEL target……修不胜修）。终解不是补字段而是**消灭双权威**：`KNOWN_TYPE_DEFER`，known-type 判定只有 Go 一个执行者。

**C3. 断言空转**——#11 overlap 反例 grep 匹配健康输出（我 27p 发现）；#6 首行 grep 被 obligation 行顶包；裸 grep `INVALID_RECEIPT` 不证明哪道 guard 有杀伤力（pr38 P1-03/pr72 之鉴）。终解：精确诊断子串 + 反断言错误 guard 未触发 + mutation sensitivity（拆守卫必红）。

**C4. 交叉污染**（codex-27l probe）——#6 六向量共用 fixture，前序席的残留红态替目标向量顶包。终解：per-vector 子 shell 独立沙盘 + 唯一分类 + event OID 归因。

**C5. Wire 声明不等于 wire 事实**——WIRE_CASES 清单只做非空守卫；第一版 stamp 又能被 require 假造（不 invoke 也盖章）。终解：只在真 invoke 处盖章 + runner 逐案核销。

**C6. Carry 谓词两连败（我的）**——`git patch-id --stable` 吞 whitespace 不是安全边界（codex 实测同 ID 否决 27s）；我改口的 tree-equality 也错（base 前进后 rebase 树必变，只覆盖 amend 情形）。终解：exact candidate fingerprint（author 字节+message 全字节+双侧 tree delta）。

**C7. Cutover 三病（pr72，进行中）**——unknown 折叠成 non-active 会**扩大**认账边界/藏匿翻转（我"只会收紧"的方向推理被真对象反例打穿）；tree-reuse 让 post-cutover 债借旧 OID 逃进认账区；认账类越出冻结授权（我把 INVALID_RECEIPT/UNJUDGEABLE 一并降级）。T_final 已修，候 gate。

**C8. Activation 自身的结构风险**（codex-27k/27f）——直接置 `active` = 永久禁写系统（UNRECORDED 债全局 WriteGuard）；activation commit 无法靠 active hctl 合自己（反循环）；`kernel=hctl@<K>` pin 与同 commit 写入自身 OID 的循环（E1 两步）。三者正是 cutover 项存在的理由。

**C9. 登记未销的残债**——首段 UNJUDGEABLE（reachable 无 squash）不认账（fail-closed 方向待 P2 repair）；测试二进制无 vcs revision 时 STALE_BINARY 耦合；`patterns_disjoint` 保守假阳；`gen_cases` drift；Go↔Python 向量级差分全量化（27o F6）；review-ledger 工具化（P2）。

## D. 模式总结（跨层规律）

**D1. 每一层"绿"都虚报过。** 脚本绿（stub）≠ oracle 绿（伪权威）≠ kernel 绿（断言空转）≠ 流程绿（未绿裸 merge）。对策一以贯之：**让绿的语义可机读**（strict manifest、stamp、唯一分类、mutation sensitivity），并立法「绿不得虚报=P1」。

**D2. 双权威必分叉，单一权威反复胜出。** Go kernel 之于 oracle、owner 之于 closure、唯一 ledger 之于横向评论、唯一 coordinator 之于 merge slot——所有拉锯的终解都是消灭第二权威，而不是同步两个权威。

**D3. 方向直觉不可靠，fail-closed 也要反例证明。** 我两次在"这个错误方向是安全的"上翻车（patch-id、"只会收紧"）。结论：**安全方向论证必须固化为 mutation 测试**，prose 推理不算数。

**D4. prose 会漂移，结构不会。** 全部有效终解都是 prose→结构的降维：署名→配置链+fail-closed 命令；里程碑→cutover commit OID；「差不多」→fingerprint；「历史债」→allowlist+边界集合。反之，凡留在 prose 的（needs 语义、trailer 规范形）都还在出问题。

**D5. 独立评审的价值被三次实证。** 同一 head 上 grok 绿 / codex 红发生三次（#65、#72 两轮）——单 gate 必漏；正确结构是"独立地审，统一地修"（barrier），而非串行或平均。

**D6. 自我修正必须留痕。** 27y→27z 更正、27s carry 修订、本篇 C6/C7 认账——错误进台账而非被覆盖，是 append-only 文化对 LLM 席位最实际的约束。
