## 1. 六条销账（F1–F6 对应 codex-27c §5；F3 并入 grok 逸出）

### F1 static assignment source 保留（checklist #6 ✗ 修复）

### F2 跨席 HANDOFF：标 DEFERRED（新增项①收口）

codex 反例成立：目标席 ACCEPT（`refs/coop/B`）与第三席超窗回池认领（`refs/coop/C`）落不同 ref，两个 lease/CAS 均可成功 ⇒ H 出现两个互斥后继——跨 ref 无互斥正是本基质物理，`pending_accept` 只覆盖 deadline 前，不裁定 accept-vs-timeout 边界。定稿：

- **P0 明记 cross-seat HANDOFF = `DEFERRED`**：状态机草案保留为 P2 设计意向，附打开条件——**必须先给 ownership transition 一个单 CAS 仲裁域**（ACCEPT 与 TIMEOUT_RETURN 在同一域串行），有 corpus 后才开放；在此之前**不宣称**「无双空/双赢窗口」。
- **P1 跨席转手走既有动词**：用户 CANCEL(claim) + 新 ASSIGN（人裁径、零跨 ref 竞态）——K-19「人=裁决」的直接应用。
- **同席换化身零协议事件**维持（codex/grok 双堂均签收）。
- **P1 事件闭集随之收缩为 CLAIM / VERDICT / CANCEL**；ASSIGN（动态）/ HANDOFF / NOTE 全在 P2。

### F3 coordinator rebind 与 activation 边界（新增项③收口 + grok 逸出）

- **rebind 语义**：merge claim 的 payload 钉 `coordinator_config_revision`（所依据的 `.hctl` 配置 blob OID）；config revision 与当前不符 ⇒ claim stale（级②）。rebind 变更本身经旧 coordinator 的 merge slot 落地 ⇒ **capacity=1 结构性保证 rebind 与其他 merge claim 互斥**（rebind PR 的 merge 占用唯一 slot，无「新旧两席各持一 slot」窗口）；落地后新 claim 只能绑新 revision。
- **activation 边界钉可重放事实**（grok 逸出同款诉求）：`.hctl` 配置含 `enforcement` 字段；P1 交付时由一个 **gated PR** 将其置 `active`（该 PR 的 required gate 即 P1 验收）。writer/loader 读 main 上当前配置：`enforcement=active` ⇒ `.hctl/**` 无 gate 变更级②拒绝、自开自合例外终止；activation 前明标级④ bootstrap trust。**doctor 硬检该字段**——例外的终点是一个 commit OID 的内容，不是里程碑 prose。

### F4 streak/frozen 确定函数（新增项④收口）

采 codex 函数原型，并给出因果锚点的具体化：

```
if escalated:
    frozen —— 仅三条显式解冻径（CANCEL(claim) / CANCEL(obligation) / 新 ASSIGN）；
    进度不清红（进度只在 escalated 前起作用，不成为第四暗门）
else:
    streak = 自最近一次「因果可证进度」以来连续 accepted replacement CLAIM 数
    streak == 1 → 黄；streak >= 2 → 红 + escalated
```

**因果可证进度 = 相邻 accepted re-claim 的 kind 锚点变化**：gate/merge 比 `revision_at_claim{base,head}`，author 比 `tip_at_claim`（认领时分支 tip OID，CLAIM payload 既有/新增字段）。锚点同 ⇒ streak+1；锚点变 ⇒ 进度插入、streak 重置。判定纯来自链上事件内容，**零采样时钟、零跨 ref 顺序依赖**。

### F5 canonical bytes 与 aspect 结构（新增项⑤收口）

- **canonical_json 钉 RFC 8785（JCS）**，P0 schema 附测试向量（含 key order / Unicode / escape 变体必须同 id、非规范输入拒绝或先规范化）。
- **aspect 改结构化对象**：gate = `{"gate_id": …, "gater_seat": …}`，author/merge = null——preimage 是结构的 canonical JSON，分隔符/转义问题整体消失（弃 `"<gate-id>:<gater-seat>"` 拼接串）。
- source 保留见 F1；「五键」勘误见头注。

### F6 评审纪律 wire form 与语义修正（新增项⑥收口）

- **scope schema 改 composite**：`scope.kind ∈ {full, composite}`；composite 含 parts——`{kind: fix_verification, findings: [finding-ids], target_blob}` 与 `{kind: delta, from_blob, to_blob}`。范围可机械重建；27f 模板的 `fix_verification+delta` 非闭集值为勘误（两堂本轮照填是遵派工，记录在案）。
- **quorum 计入条件收紧**：required quorum 只认「exact target revision + COMPLETE + APPROVE + **scope 覆盖 assignment 要求的评审面**」四条件齐备的 verdict；窄 delta 上的 COMPLETE 不得冒充全量批准。
- **恢复 merge 前逸出的阻断力**（撤回 27f「一律不阻塞」）：merge 前 late finding = 该 gater 对同 revision 发 latest-wins verdict，**REQUEST_CHANGES 即失绿阻断**（fail-closed）；merge 后 = NOTE + 人裁修复 assignment。「不重启已封口范围」保留——阻断走正常 verdict 通道，不重开评审面。
- **收敛表述降格**：撤回「收敛保证由构造给出」，改为「**构造性促进收敛并使逸出可审计**」；如需终止保证，由用户终裁 / round budget / well-founded 变更度量另行提供，不从 scope 单调性推出。
