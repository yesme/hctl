## 2. Findings

### P1-01 — PR 修改自身 frozen assignment，合并后旧 quorum/receipt 必然失配

**位置**：`.hctl/assignments/p1-attribution.toml:4-5`。

PR 为记录开工令而改了两行注释。D-33 的 assignment revision 是完整 blob，不区分“仅注释”；因此当前正在评审的旧 blob 与合并后新 blob 派生出两套完全不同的 obligation：

```text
                         old blob 3006b502...        new blob fa277c580...
precision gate           sha256:280046d8...          sha256:ea9df7eb...
spec-conformance gate    sha256:fead83880...          sha256:501653f7...
merge                    sha256:9ee70c85...          sha256:d6ab72e3...
```

当前两席只能对 old obligation 投票，merge claim/receipt 也只能钉 old merge ID。PR 一旦进入 main，loader 看到的却是 new blob；`validateReceiptReplay` 要求 current assignment blob 在 `Hctl-Base` 原样存在，旧 base 不可能含 new blob。结果不是“注释随实现一起合入”，而是旧 receipt 不能关闭新义务，产生 `INVALID_RECEIPT`/新一轮 assignment obligations。

**要求**：本 PR 完全撤回 `.hctl/assignments/p1-attribution.toml` 的变更，使 base/head assignment blob 字面相同。用户开工令已由对话与 author memo 记录，不应原地改写已冻结 assignment。

### P1-02 — `local.toml` 放在 common dir，当前三席 linked worktree 会互相覆盖

**位置**：`internal/identity/local.go:13-25`、`internal/app/seat.go:65-94`。

实现使用 `repo.CommonDir/hctl/local.toml`，但本仓 claude/codex/grok 正是同一 clone 的三个 linked worktree，共享 CommonDir。精确 head 上的临时双 worktree 反例：

```text
grok  seat init:
  seat=grok
  email=grok bot
  path=<clone>/.git/hctl/local.toml

codex seat init:
  seat=codex
  email=grok bot                 # 继承了共享文件中的旧 email
  path=<clone>/.git/hctl/local.toml

codex trailer:
  exit 0
  Co-authored-by: GPT-5.6 Sol (max effort) <302482056+a-grok-build-bot[bot]@...>

grok trailer after codex init:
  exit 1
  local attribution seat "codex" does not match current seat "grok"
```

相邻对照中，Git 对两个 worktree 的 `git rev-parse --git-path hctl/local.toml` 给出两个不同路径：

```text
<clone>/.git/worktrees/grok-wt/hctl/local.toml
<clone>/.git/worktrees/codex-wt/hctl/local.toml
```

这不是边缘部署：它就是本仓零号采用者的物理拓扑。当前实现使三席无法同时完成 init，并在正常顺序下直接生成错 bot trailer。

**要求**：seat/email 状态必须按 worktree 隔离（或采用等价的无覆盖键控设计）；从一个 seat 切换到另一个 seat 时禁止沿用旧 seat 的 email。补 linked-worktree 集成测试，必须证明两席 init 后各自 trailer 仍稳定且互不改写。

### P1-03 — 产出命令未执行 seat↔email 所有权校验，和 doctor 同 payload 分叉

**位置**：`internal/app/seat.go:105-138`、`internal/app/trailer.go:39-48`、`internal/app/doctor.go:160-188`。

`ResolveCoauthorEmail` 对 env/local 只做极弱形状校验后立即返回；跨席 bot 检查只存在于 `doctor`。同一 exact head、同一 seat 和同一 env payload 的机械差分：

```text
seat=grok
HCTL_COAUTHOR_EMAIL=281844019+a-claude-code-bot[bot]@users.noreply.github.com

hctl trailer:
  exit 0
  Co-authored-by: Grok 4.5 (high effort) <281844019+a-claude-code-bot[bot]@...>

hctl doctor:
  exit 1
  attribution error: email is configured for seat "claude", not current seat "grok"
```

原提案正是为消除“Grok 模型 + Claude bot”事故；生产 trailer 仍可原样重现该事故，事后 doctor 报错不能构成 fail-closed。`hctl seat init --email <他席 bot>` 也会写入并报告成功。

**要求**：把 seat↔known-bot ownership 变成单一共享 validator，并让 `seat init`、env/local/seats resolution、`trailer` 与 `doctor` 使用同一判定。自定义且不属于其他已知 seat 的 override 仍可按规格允许；已配置给另一席的邮箱必须在产出前拒绝。local seat mismatch 也不得因 env precedence 被绕过。

### P1-04 — `seat init`/`trailer` 新增全量远端观察，违反显式离线验收

**位置**：`internal/app/app.go:109-128`、`internal/app/seat.go:48-54`、`internal/app/trailer.go:28-35`。

两条本地命令都调用 `a.load`；`facts.Observer.Observe` 第一阶段就是 `git ls-remote`，失败后不会加载 seats。精确 head 上，已持久化正确 local seat/email 且 model/effort env 完整，只把 origin 改为不可达：

```text
hctl trailer  -> exit 1: seats configuration is unavailable for trailer email resolution
hctl seat init -> exit 1: seats configuration is unavailable
```

远端可达时同一 payload 成功。该单变量 happy/fail pair 违反 grok-27j §6 第 5 项的“仍为零常驻、无网络（除既有 gh 路径）”，也把原本纯本地的 pre-commit helper 变成网络故障时不可用。

**要求**：为 attribution helper 建独立的本地加载路径；不得经过 ref-plane observer。离线时，在本地证据完整且一致的前提下必须能 init/产出；缺失或冲突仍 fail-closed。补一条把 origin 置为不可达的命令级回归。
