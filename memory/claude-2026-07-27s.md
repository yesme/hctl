## 2. 技术修正：carry 谓词从 tree 等价改为 patch-id 等价

27q「最后一次 rebase 预期 tree 恒 8d913d5」与 27r B2 第一条件 `tree(head)==tree(head')` **有错**：base 前进含新文件（如 memo 落 main）时，rebase 后的 head' 树必然包含这些文件，tree 等价只成立于同 base 改-message/amend 的退化情形。codex §5 的谨慎（"base-only 前进更适合比较 PR patch 与治理面"）正中此穴。修订为：

```text
carry(V{base,head} → {base',head'}) ⇔
    V.decision==APPROVE ∧ V.completeness==COMPLETE      # 只继承绿票；RC 不继承
  ∧ is-ancestor(base, base')                            # base 只前进、无回卷
  ∧ patch_id(base..head) == patch_id(base'..head')      # 评审面语义等价（git patch-id --stable；
                                                        #   同 base 改-message 情形自然退化包含）
  ∧ tree_at(base, .hctl/) == tree_at(base', .hctl/)     # 治理面等价（挡 rebind/enforcement/assignment 类）
```

- patch-id 不等 ⇒ 全额重审；不做任何"看起来无关"的模糊判断（grok §4 红线原样有效）。
- 继承在 status 显像 `carried: patch-equivalent`，计票可解释、审计不失。
- amends D-04/D-40（计票例外）随实现 PR 同批落 DECISIONS。`p1-regate-carry` 提案照此规格修订，仍候用户授权（author=codex 建议不变）。

## 3. 收敛协议（语义层四条，即刻以级④生效，P2 机械化进 ledger）

1. **Ownership**：finding 只能由 originating gater 关闭。他席只写 supporting/conflicting evidence；author 只声明 `ADDRESSED`；跨席状态词全仓统一为 `ADDRESSED / CLOSED(owner-only) / NOT_EVALUATED / OUT_OF_SCOPE+owner`。（27q 那类"✅+注缺口"表达自此违规——本席先改。）
2. **corpus DoD 规则（冻结为严重度法条）**：交付物是 required gate corpus 时，「规范实现坏掉而测试仍绿」本身即 P1，不因 kernel 侧另有单测而降级。（27n F1、codex 两轮 RC 的分歧根源就地终裁；spec-conformance 与 precision 两镜头自此共用这条底线。）
3. **Closure kit（author 举证责任反转）**：每条 P1 finding 的销账须五件套——原始反例原样固化、相邻 mutation、oracle/kernel 同 payload 差分（如适用）、mutation sensitivity（拆守卫必红）、happy/fail-closed 成对。author response 写"如何证明关闭"，不写"改了什么"。
4. **Reconciliation barrier**：两席独立审同一 frozen head 之后、author 动手之前，coordinator 把两份 findings 归一成唯一 ledger（ID/owner/severity/closure 冲突就地调解，调不拢上提用户）。author 每轮只收一个批次、只 push 一次。独立性保留在"审"，统一发生在"修之前"——不串行化 required gates。

## 4. 统一 round 协议（②+③合体，即刻生效）

```text
0. 用户授权 assignment（merge-readiness 依赖必须结构化为 needs，禁 prose 承诺——R1 法条）
1. 机械 preflight：assignment/branch_slug/needs/PR/obligation/trailer 全成立才开工
2. author 自验后发布 frozen candidate T（此后 freeze tip）
3. required gates 并行独立审 T
4. reconciliation barrier → 唯一 finding ledger
5. author 一次性处理整批 → 只 push T2 一次
6. owner gater fix_verification + delta（默认 composite，禁默认 full）
7. verdict memo 只开 PR 不合 main
8. coordinator 批合全部 quorum memo → author 一次最终 rebase
9. carry 谓词机械继承（落地前：一行 re-nail 顶替）→ 静默窗口立即 squash
```

效果指标（codex §6 采纳，coordinator 在每个 assignment 收口 memo 记录）：author push 次数、gate 轮数、re-nail 次数、reopened finding 数、severity 分歧数、mutation 杀伤率、preflight 命中数。目标不是零 RC，是：同一 finding 不二开、每轮一个批次、语义修复只产生一次新 head、非语义前进不触发 full、未绿在机械层不可 merge。
