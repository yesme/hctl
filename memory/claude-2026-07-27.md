## 1. 五家评估的立场图（输入综合）

**四家独立收敛的共识**（不再辩）：独立 repo（工具的家）+ 信号留工作仓；level-triggered derive（通知只唤醒、状态全量推导、漏醒无害）；宽进严出、title 永不作判据、信号结构化；verdict 钉 exact head SHA；gate 属性正交轴 + quorum 布尔式、blocking 禁 silent skip、deputy 预声明；活性降 UX、取消全局 interrupt；DAG 与 ad-hoc 统一执行语义；事故语料=验收测试；机械层零 LLM；能力矩阵是配置不进内核。

**立场差异**：
- 事实源：claude+grok 主张 git refs 权威（评论镜像）；codex 主张 PR 评论内嵌 marker 权威（ETag 轮询）；glm/kimi 偏评论通道但用 refs 做唤醒。grok 给出关键论证：用户愿望「不 access API 也能 handle comments」逻辑等价于「comment 不是唯一真相」。
- 分支：codex 独家提出 work/<harness>/<task-id> 任务分支取代 machine-suffixed 长期分支。
- 本地状态：codex 要 SQLite 缓存 + 每机常驻 watcher；claude 要纯 derive 无状态。
- 等待语义：glm 要显式锁+人工裁决反对隐式等待；claude 提起草流水线+memo 白名单豁免；grok 提「写锁在发布不在思考」；codex 说内核持队列则等待无害。
- agy 对旧 ROUND-PROTOCOL 的背书中值得继承的：静态 DAG 即全部授权、fail-closed（宁停摆不带病合入）——在新架构中分别保留为「无边不动作」与「required gate 缺席=不 merge」（而非杀进程）。

## 2. 定案清单（K-01…K-24，DECISIONS.md 待转录；标注定案来源）

> 来源标注：〔用户裁〕= 用户明示或用户论证驱动；〔主笔〕= claude 立场、用户未反对、待会审确认。

- **K-01〔用户裁〕三层承载**：①事件层 `refs/coop/<seat>` append-only 链（小 JSON：VERDICT/EDGE/HANDOFF/CANCEL/NOTE，一律钉 head SHA；git transport 读写零 REST；跨机 push/fetch）；②叙事层 memo lane（`memory/<seat>-<date><seq>.md`，微 PR 即合上 main；review 全文、架构、设计、讨论的家；clone main 即得全部考古）；③变更层 PR 本体（任务分支、head、merge 状态；GitHub 只当 merge 机器）。定案动因是用户原话：「我在意的不是 github 页面上可考古，而是**git repo 里可考古**。所有 review 的过程内容和考虑我都不希望丢失」。推论：**GitHub 页面零义务**——工作流中不再有承载语义的 PR 评论（谁写了是装饰，永不阻塞永不路由）；gh 用量收缩到 `pr create`/`pr merge` 两条；ETag 评论轮询整套退出关键路径。链接纪律：VERDICT 带 `memo:` 指针；先合 memo 后落事件。代价（已明示）：clone 默认不拉 refs/coop/*，消费仓配一次 fetch refspec（doctor 检查）。
- **K-02〔共识〕Level-triggered 轴心**：通知只唤醒不携带语义；状态永远是 derive(git 事实) 的纯函数输出；漏醒/多醒无害；**每次调用即全量 reconcile**（无独立 reconcile 动词、无本地权威状态）。
- **K-03〔共识〕宽进严出**：任何 ref 变化都可唤醒；判定只认结构化字段全匹配；title/自由文本/regex 永不作判据（「按内容理解」修正为「读结构化语义」，不引 LLM 路由）。
- **K-04〔共识〕Verdict 钉 head**（Gerrit patchset 语义）：head 动 → 该 head 全部判定自动 stale 回欠账。
- **K-05〔主笔〕Gate 代数 = 四可配轴 + 两条法律**：轴 mode(required/advisory/observe) × quorum(布尔式，submit requirement 形态) × threshold(P0/P1/all) × on_timeout(escalate/预声明 deputy/仅 advisory 可 proceed)。法律（不可配置）：freshness 钉 head；gater≠author。required 永不静默跳过。原为 codex 五轴 + kimi independence 轴，主笔将 freshness/independence 从旋钮升格为法律（「旋钮最少化、法律最大化」）。
- **K-06〔共识〕活性降 UX**：无 round 心跳义务、无全局 interrupt、sidecar/watchdog 退役；**overdue 是推导事实不是触发事件**（从事件时间戳算 now>T+W，任何时刻跑 status 都可见；无进程存活要求）；黄灯只展示，动作（催/deputy/cancel）显式。人用 `hctl cancel` 显式取消（钉定范围的事件），与误判毒杀彻底分开。
- **K-07〔主笔〕边统一**：DAG=冻结边集文件（`.hctl/edges/`，merge 进 main 即封存=全部授权）；ad-hoc=一条 EDGE 事件（即派工单，驻班者 wake 可见）；derive 时同形，worker 只认边。取代 codex 的独立 WorkOrder 编译产物（判过度机械）。
- **K-08〔用户裁〕Session/任务分支取代 machine 长期分支**：`work/<seat>/<slug>`，合并即死；机器名退出远端命名空间（回本地 worktree 路径与自报文本）。用户自己给出论证：「可能 **session 才是唯一的信号**」；hosted session 的 provider 生成分支是活先例。三病根同消：post-squash 复位仪式、force 竞态、双后缀类事故（grok-mac-mac）。分支 pattern 是消费仓约定（schema 校验），内核不硬编码；derive 从分支名直推 PR 归属（省掉 OPEN 事件）。
- **K-09〔共识〕单写者命名空间三粒度**：分支（一任务）、文件（一实例：memo 前缀+date+seq）、ref（一席一链）。conflict-free 是构造出来的不是协调出来的。用户点出 per-harness-instance 特性正是并行讨论与独立意见记录的基础。
- **K-10〔用户裁〕Memo lane 定性**：文体是**流水账**不是文档；内核对 memo 正文**零解析零 schema**（opaque blob；结构只在事件层）；与 PR 平级的工作产出类（承载架构/设计/讨论，不只 review）；不占 slot、advisory、即合、永不上 author 分支（claude 原 memo 白名单豁免案废弃）。知识默认走流水账，需收敛才升格共享文档（共享写→回落 author-class 流程）。
- **K-11〔主笔〕咨询模式立名**：同一 brief 扇出 N 席 → 各自独立落 memo（防污染纪律在 prompt 层）→ 综合。与 PR 流程平级；内核贡献=conflict-free lane；可选 NOTE 事件报「已交卷」。本次 hctl 设计即此模式产物。
- **K-12〔主笔〕Plan 架构 = 渐进固化管道**：发散（咨询扇出）→ 综合（synthesis memo）→ 裁定（DECISIONS 条目）→ 封存（edges 文件，author-class PR 可被 gate）→ fire（人）。plan 的终点=内核的输入。
- **K-13〔用户认〕交互模型**：hctl 是**叶子命令**不是编排器——不开窗口、不起服务、不驱动 harness、不替代 Ghostty；席位=worktree=tab 三位一体；唯一前台阻塞动词是 wake；输出三形态（人读表格 / --json / exit code）；**自描述输出**（status 每行欠账自带下一步动作，wake 退出打印「什么变了+policy」——弱模型跟着输出走即可）。
- **K-14〔共识〕并发物理层**：git index 是 per-worktree 的，一 index 一写者 → worktree 粒度 ≥ 并发写者粒度；**一 seat 一常驻 worktree 保持不变**（解耦的是 worktree↔分支，不是 seat↔worktree）；常驻 worktree 的 checkout 权属前台 session，`git switch` 只发生在前台任务边界；后台一律零 checkout——对象库直读（`git show`/`git diff origin/main...FETCH_HEAD`）优先，需完整树用一次性 scratch worktree（`hctl scratch <pr>`，共享对象库秒建即删）；旁路发布（memo/事件）走 plumbing（commit-tree），不借任何工作目录。
- **K-15〔主笔·推荐实践非法律〕Session 粒度 = 任务粒度**：一 author 任务一 session；一 gate 指派一 session（**覆盖完整 re-gate 循环**——delta 复审吃热上下文）；一咨询话题一 session。fresh-session-per-gate = 盲评的机制化。一 seat 并行度放 session 内 sub-agent（读类、写收口主循环），不放多顶层 session（两顶层 session 同 worktree=两写者一 index）；真需第二顶层写者显式开第二 worktree。**session 是 cache，memory 是数据库**。sub-agent 本质=一次性新开的 LLM 上下文（同权重、干净 context、报告后蒸发）；可 resume 的是顶层 session；子代理花同账户 token，扇出即乘法（GLM/Kimi 类紧 token 席位要节制）。
- **K-16〔用户提出主笔展开〕Context 经济学**：cache TTL 分钟-小时级 → 跨日温度是幻觉；真实对比=「每任务付一次 prefill」vs「每轮付膨胀+冷启动照样全额」；同批扇出统一前导吃前缀缓存；**知识金字塔**：门面(AGENTS/COLLABORATION，1-2 页硬预算)→现状(台账)→结论(DECISIONS)→正文(共享文档)→考古(memory，默认不读指针驱动)；知识必须持续向上迁移——**收口(closeout)立为标准节点类型**（round-01 #15 台账收口的泛化），是排班内编辑工作不是后台服务；派工 brief 带指针不带语料（精确路径+钉死 SHA）；AGENTS 片段稳定内容前置。
- **K-17〔用户裁〕执行等级第一原则**：违规不是品行问题是设计问题。四级阶梯：①结构不可能 ②机器拒绝（hook/包装命令）③机器审计 ④LLM 自觉。**每条不变量必须标注执行等级；无执行方案的规则=设计债**；第 4 级条目必须少、点名、配兜底。两手法：**LLM 只做选择题**（head/ref 名/日期/trailer 全部工具生成，LLM 只给语义输入）；**最强执行是删规则**（心跳义务废除即范例）。语料测试测的是护栏不是 LLM 行为。信任边界明写：free 私有仓无服务端保护+单人类账号 → 护栏防失误与漂移不防恶意；恶意场景=审计+forward-only 修复。
- **K-18〔共识〕监听面 = ref 平面不是文件系统**：一条 `git ls-remote origin` 全量覆盖（refs/pull/*/head、refs/heads/work/*、refs/coop/*、main）；wake 内部=30s 快照 diff（§8 已实战配方产品化，固定间隔）→ derive 判相关性（宽进严出）→ exit 0/exit 2(timeout)；快照缓存在 .git/hctl/ 可丢；无人等待时系统里没有任何东西在跑；本机共享 .git 使一家 fetch 全员受益。
- **K-19〔用户问出主笔定〕驻留模式**：TUI turn-based、无 turn 不动，但 turn 可任意长——**驻班**（fire 一次进入 wake↔work 自循环，消化 derive 名下欠账：author 节点/gate/quorum 齐后的 merge；直到回合结束或 escalate）vs **待命**（需开工/`hctl run` 拉起）。EDGE 事件即派工传播（在 codex tab 说「让 claude gate」→ claude 驻班 wake 30s 内自接）。驻班两条安全边界：授权边界（无边不动作，意外一律 escalate——继承「DAG 即全部授权」）、班次有界（round 为班次，收班=落 memo+结束 session）。**人的角色终局收敛为：排班、开工、裁决**。
- **K-20〔用户裁〕轮子复用三层**：①直接复用（系统重量九成）——git 本体（worktree/notes/trailers/hooks/plumbing/ls-remote）、GitHub PR+squash+gh、§8 等待配方、coauthor.py 证据归因、abacistopia hooks 模式；②借语义与命名——**naming policy：凡有业界既有名词不自造**（业界词在预训练语料里=白拿的 few-shot，自造词每 instance 都要重新教）：quorum 表达式→Gerrit submit requirement 形态、verdict 钉 head→patchset 语义、欠账→attention set、verdict 值→GitHub 的 APPROVE/REQUEST_CHANGES（弃 PASS/RC）、trailer 词汇→kernel 的 Reviewed-by/Acked-by、并行分类→Zuul 的 independent/dependent/serial、按路径派 gater→CODEOWNERS/OWNERS 形态、推导→K8s 的 reconcile/level-triggered；自造词仅 **seat**（席位制原创）与 **memo lane**（业界无对应），自造须自证必要；③必须自写的薄壳——derive/slot/EDGE-HANDOFF 事件/wake 判定/seats 围栏，千行级 python。**不部署 Gerrit/Zuul/Prow**：四不匹配（常驻服务、多真实账号身份模型、CI-job worker 形态、取代 GitHub PR 载体）——抄模型不抄部署。
- **K-21〔主笔〕git-appraise 特别处置**：最近亲戚（无服务、review 入 refs——refs 事实源直接先例），但整体采用不划算（只覆盖 review 子集，derive/slot/quorum 仍要自写，schema 不为 PR+quorum 设计，维护半休眠）。引出 P1 待定项：**事件层基质用裸 ref 链还是 git notes**（`refs/notes/hctl/<seat>` 每席一 notes ref 保持单写者；notes 优势=verdict 天然是挂在被审 commit 上的元数据、锚定即钉 head、porcelain 支持）。不改上层设计，纯实现选型，P1 前通读 git-appraise schema 再定。
- **K-22〔用户问出主笔定〕Harness 接入三件套**：①AGENTS-<seat>.md 最小片段（≤10 行常驻：身份+status/wake 两动词+「详情跑 hctl help」；稳定前缀友好）；②**hctl help = canonical 文档**（与二进制同版本永不漂移；lazy-load 普适接口=shell 执行）；③SKILL.md 薄壳（可选增强：触发器+「跑 hctl help 照办」，与 help 同源生成，**不装 readme 正文**——六份副本必漂移，违反单一真相源）。支持度：AGENTS.md 系事实标准全员可用；SKILL 格式 Claude 原生、Codex/OpenCode 大概率（需实测）、Kimi/Grok/AGY 未知——逐家实测入 seats.toml 能力注记（与 session resume/subagent 支持同一张清单）。
- **K-23〔主笔〕归因三通道**：命名空间单写者（机器判定身份）+ 证据化 trailer（coauthor.py 收编为 `hctl trailer`，commit 级归因；模型+effort 从会话证据取，取不到即拒绝）+ 人读自报（`by <seat>-<machine>` 仅对账）。GitHub actor 永不作身份判据（单账号）。
- **K-24〔主笔〕实现形态**：Python 3 stdlib 单包零 pip 依赖（配置 TOML、事件 JSON）；shell 仅薄壳。理由：事故语料要可执行化为回归测试；round-01 两起工具链事故（sidecar 探针路径、wait_tick 双后缀）均为 shell 字符串病；gate.py/coauthor.py 已是 python 先例。

## 3. 对各家意见的取/改/弃（主笔独立立场，用户要求「自己的方案不照单全收」）

**弃**：codex 的 SQLite 本地状态+每机常驻 watcher（违叶子命令模型；无缓存即无缓存谎言；ETag 降级为 wake 内可选辅助）；codex 的 GitHub Action/ruleset 强制阶段（整条砍出路线图——free 私有仓 branch protection 物理不可用，且单账号信任模型下是安保剧场）；codex 的独立 WorkOrder 编译产物（简化为边，K-07）；glm 的 ad-hoc gate 配置写 PR body frontmatter（body 是 GitHub 数据库数据、可编辑、要 REST 读——与评论同坑；边声明与其他边同家）；kimi 的 2s 轮询入规范与 last-seen cursor 死信（轮询节奏是实现细节；level-triggered 下欠账列表即死信清单）；claude 自己的 memo 路径白名单豁免（grok/codex 说服：memo 永不上 author 分支，内核零路径特例）。

**改**：codex 任务分支采纳但降为消费仓约定（内核只校验 pattern）；codex freshness 轴与 kimi independence 轴升格为法律（K-05）；claude 起草流水线保留且推到底——「写锁在发布不在思考」（grok 表述）：起草连登记都不用，内核只在 pr create 时刻查 slot。

**取**：level-triggered（四家）；宽进严出（四家）；blocking 禁 silent skip + deputy 预声明（claude/grok）；活性降 UX + 显式 cancel（claude/grok）；事实源 refs 权威（claude/grok，用户以「git repo 可考古」裁定并推进为 K-01 三层承载）；事故语料=验收测试（全员）；工具家/信号家分离（claude/grok）；「一份规范+一份配置+一个程序+可丢本地缓存」收束形态（codex/grok 同表述）。
