#### 否决 patch-id

实测两份 Python patch：

```diff

```

与

```diff
+    if ready:
```

经 `git patch-id --stable` 得到同一
`1064f64a26deff8f95964a5dfdb8393ecc64cb5d`。因此 patch-id 是相似补丁工具，
不是 security boundary。

#### v1 carry 的机械谓词

定义 exact candidate fingerprint：

```text
candidate_fp(base, head) =
  hash(
    ordered first-parent candidate commits:
      author identity
      full commit-message bytes
      exact tree delta against parent:
        sorted(path bytes, old mode/type/blob-or-absent,
                           new mode/type/blob-or-absent)
  )
```

它保留 whitespace、binary、mode、rename-as-delete/add 与 trailer；排除 rebase 必然变化的
parent OID、committer timestamp。非线性 candidate 直接不 carry。

```text
carry(V{B,H} → {B',H'}) iff
    V.decision == APPROVE
  ∧ V.completeness == COMPLETE
  ∧ is_ancestor(B, B')
  ∧ same assignment / gate obligation / PR / branch
  ∧ candidate_fp(B,H) == candidate_fp(B',H')
  ∧ changed_paths(B,B') ⊆ memory/**
  ∧ changed_paths(B,B') ∩ candidate_paths(B,H) == ∅
  ∧ no newer verdict supersedes V
```

任何一项不可证即不 carry。尤其：

- `.hctl/**`、DECISIONS、METHOD、schema 或源码 base 前进：不 carry；
- commit message/trailer 改动：不 carry；
- REQUEST_CHANGES/INCOMPLETE：不 carry；
- “看起来无关”、时间窗、latest 自动继承：不做。

path-disjoint code/docs carry 仍留 P2，前置 review-surface/dependency map；v1 只解决本轮
已经实证的 memo-base 自激振荡。

### Author

### Peer gater

- 对他席 finding 只写 supporting/conflicting/NOT_EVALUATED；
- 不再出现“✅，但尚有缺口”；
- 严重度冲突在 author 动手前解决。

### Coordinator

- 先 reconciliation，后 author repair；
- round 内冻结 main，批合 memo；
- round budget 到点必须 merge/ESCALATE，不得默许下一轮；
- activation 后 merge 只走 hctl，不猜 PR 号。
