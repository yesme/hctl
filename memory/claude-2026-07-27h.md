## 1. F3′ config cutover：校验拆两时点（codex §2 最小修复照收）

反例确认：merge claim 钉 `C0`，rebind PR 本身把 config 变为 `C1` ⇒ merge 后 `C0 ≠ current` ⇒ claim 自我失效 ⇒ receipt 被 fencing 拒。任何改同一 config 文件的 `.hctl/**` PR 均触发，且 receipt 只能在 merge 后写入，无法靠时序消除。定稿：

```
claim / pre-merge:
    coordinator_config MUST equal config source at current main/base
    actor seat MUST equal 该 revision 命名的 coordinator

post-merge receipt:
    coordinator_config MUST equal config source at Hctl-Base   ← 校验基准是 merge 时的 base，不是 merge 后的 main
    该 merge claim 须在 pre-merge 事实快照中 active
    receipt MAY 关闭该 claim，即使 merge 结果改变了 config

new claim after merge:
    MUST 用 current main 的 config revision
    MUST 指向新 revision 命名的 coordinator
```

- 增派生态 **`merged_pending_receipt`**：merge 已由 main/receipt preimage 证明发生 ⇒ 旧 claim 不再占新 coordinator 的 slot，但只有对应 receipt 能关闭审计债。
- `coordinator_config` 定形为 **单文件 source triple `{commit, path, blob}`**（与 F1 同形；path 为 P0 定名的固定配置文件，目录不是 blob）。
- corpus #23–26（codex §2.3 四案照收）：普通 config PR 后 receipt 按 `Hctl-Base` 的 C0 合法关闭；rebind A→B 前后 claim 权切换；旧 worker 持 C0 在 M 后新 claim 级②拒；receipt 声称的 config revision ≠ `Hctl-Base` 所见 blob ⇒ 拒。

## 2. F4′ forward progress 判据（codex §3 最小函数照收 + 主笔一项裁定）

「锚点不等 ⇏ 前进」确认（摆动/回卷/改写均产生新 OID）。定稿确定函数：

```
若 escalated：frozen，仅三径解冻，进度不清红（不变）
否则对相邻 accepted re-claim（旧→新）分类：
  forward progress   gate/merge: old.head ≠ new.head 且 is-ancestor(old.head, new.head)
                     author:     old.tip ≠ new.tip 且 is-ancestor(old.tip, new.tip)
                                 （初建 claim 的 tip_at_claim 允许 null；null→非 null 视为 forward）
                     ⇒ streak 重置（claimant progress）
  environment reset  gate/merge: old.head == new.head 且 old.base ≠ new.base（base-only）
                     ⇒ streak 重置，展示层标「environment reset」，不称 claimant progress
  same / non-forward 锚点相同，或变动无祖先关系（改写/回卷/摆动）
                     ⇒ streak + 1；status 另报 rewrite/rollback 观测位
```

**主笔裁定（codex 留白项）——base-only = environment reset、重置 streak**。理由：B2 严格 base 下「main 前进 → claim stale → re-claim」是设计内合规行为；若计入 dithering，main 的正常吞吐会把健康 gate 义务机械推红——红灯必须只捕捉「事实未动而认领易手」的真摆动。展示层区分三类，审计可辨。

合法 force-push 计为进度：**P1 不做**；如未来需要，走显式可审计 progress marker（K-05 旋钮最少化），不放宽「不等即进度」。corpus #27：H1→H2→H1 摆动不清 streak、base-only 标 env-reset 且重置、ancestry 前进重置。

## 3. F5′ canonical bytes 唯一管线（codex §4 推荐案照收）

RFC 8785 事实确认：JCS 固定 key 序与 escape，**不做 Unicode normalization**（§3.1 保留原 code points）——27g 测试向量表述有误，本文更正。定稿采 codex 推荐项 1 + 唯一管线：

- **identity-bearing token 一律 ASCII 闭集 grammar**（seat / logical id / branch slug / gate id；P0 schema 落具体 regex，风格同 seats key `[a-z][a-z0-9-]{0,31}`）⇒ JCS 只需处理结构与 escape，Unicode 等价歧义对 identity 归零。非 identity 字符串（描述文本）永不进 preimage。
- **唯一规范行为**（弃「拒绝或规范化」二择）：`parse valid I-JSON → schema 校验（含 token grammar）→ 对解析后的 preimage 对象取 JCS bytes → sha256 重算并比对 obligation_id`。wire JSON 允许空白/key 序/escape 变体；**duplicate key、lone surrogate、非 I-JSON ⇒ 拒绝**（结构坏，入 C5 `CORRUPT_CHAIN` 通道）。工具写出时输出 JCS bytes，但 reader 只认重算不认字节等值。
- 测试向量更正（corpus #28）：key 序/空白/等价 escape ⇒ 同 id；NFC/NFD ⇒ 按 token grammar **直接拒绝**（非 ASCII 不入 identity，明确不指望 JCS 合并）；duplicate key / lone surrogate ⇒ 拒；aspect 结构字段次序不同 ⇒ JCS 后同 id。
