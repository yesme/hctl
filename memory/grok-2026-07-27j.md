## 1. 问题

归因（模型名 + effort + co-author email）今天依赖：

- AGENTS / 自然语言 policy（级④）  
- 人脑抄 abacistopia 先例  
- `hctl trailer` 只读三个 env，**不发现**、不校验 seat↔bot 匹配  

结果：LLM 抄错邮箱 → GitHub 接到错误 bot（本次：`a-claude-code-bot` 而非 `a-grok-build-bot`）。  
与 D-17「违规是设计问题」/ D-23「证据化 trailer、取不到即拒」同构——abacistopia 已用脚本+hook 收口，hctl 应收编（D-24 亦点名 coauthor.py）。

## 2. 目标

把「席位本地基本信息 + 会话归因」从 prose policy 收成 **叶子命令 + 本地状态 + fail-closed**，使：

1. bot 邮箱等 **有 default**（来自 seats 或 harness 表），本机一次 setup；  
2. 模型 display name / effort **无 default**——必须从 **当前 session 证据** 解析；  
3. `hctl trailer`（及未来 commit helper）输出唯一合法 trailer 形，缺证据即拒；  
4. **不**做成常驻编排器（仍 D-13）。

## 3. 分层（建议）

### 3.1 仓级共享（main，gated）

`.hctl/seats.toml` 已有 seat 声明。可演进每席 **stable 归因模板**（不进 obligation identity / 不进 quorum）：

```toml
[seats.grok]
harness = "grok-build"
# 现有 pattern / capabilities …
coauthor_email = "302482056+a-grok-build-bot[bot]@users.noreply.github.com"
# 可选：display 族名提示；禁止当作本回合 model 证据
```

变更走 D-38 配置 gate。default 可被机本地 override。

**abacistopia 已验证 bot 邮箱（现行）：**

|---|---|
| grok-build | `302482056+a-grok-build-bot[bot]@users.noreply.github.com` |
| claude-code | `281844019+a-claude-code-bot[bot]@users.noreply.github.com` |

### 3.2 机/席本地（不进 main）

路径建议：`.git/hctl/local.toml`（旁路已有 `machine` UUID 文件）。

`hctl seat init`（或 `hctl setup`；**避免**裸 `hctl init` 与 `git init` 混淆，或 `init` 仅作仓脚手架别名）：

- 探测/确认 seat（worktree 后缀、分支 pattern、`--seat`）  
- 写入：seat、harness adapter 键、coauthor_email（default←seats.toml）、可选 machine 别名  
- idempotent；`doctor` 检缺失/冲突  

### 3.3 会话实况（禁止 default 顶替）

按 harness adapter 读 **session 证据**（仿 abacistopia `scripts/coauthor.py`）：

- grok → `~/.grok/sessions/**/<id>/summary.json` 的 model + reasoning_effort  
- claude / codex / … → 各家既有证据源  

`hctl trailer`：

```
Co-authored-by: <model> (<effort> effort) <<email>>
```

email ← 本地 setup ∪ seats default；model/effort ← session only。  
任一不可得 → exit ≠ 0（D-23）。  
可选：`commit-msg` hook 或 `hctl commit` 薄壳 = 级②强制。

## 4. 命令面草图

| 命令 | 作用 | 阶段建议 |
|---|---|---|
| `hctl seat init [--seat] [--email]` | 写本地 local.toml；default 从 seats | P1.1 |
| `hctl trailer` | 强化：读本地 + adapter 取 session；不再只靠裸 env（env 可作 override 显式） | P1.1 |
| `hctl doctor` | 增：归因链是否可解析；seat↔email 是否像已知 bot 表 | P1.1 |
| seats.toml `coauthor_email` 字段 | schema + loader | 随 setup 同批 |
| adapter 插件/内置表 | 各 harness 证据路径 | 先 grok+claude+codex，其余 P2 |

**不在范围：** daemon 盯 session 自动 commit；hctl 驱动 harness 进程（仍 adapters / 人开工）。

## 5. 与现行命令关系

- D-43 已列 helper `trailer`；无 `init`——本提案为 **P1.1 增量**，不改 P1 竖切 correctness 闭集。  
- machine UUID 自动持久已存在（`identity.Actor`）——setup 与之并存、不重复发明。  
- 与「LLM 只做选择题」一致：commit 时模型不填邮箱串，只 `hctl trailer` 或 hook 注入。

## 6. 验收草（将来 corpus / doctor）

1. 未 `seat init` 且无完整 env → `trailer` 红。  
2. init 后 session 证据齐全 → trailer 形固定、email=bot 表。  
3. 伪造/缺失 effort → 红，不静默省略。  
4. seats 声明 grok 却 local email 为 claude bot → doctor 黄或红（策略二选一，建议红）。  
5. 仍为零常驻、无网络（除既有 gh 路径）。
