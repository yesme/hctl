  duplicate key、非法 UTF-8、lone surrogate 拒收；JCS 手写，包含 UTF-16 key order 与
  ECMAScript number boundary；obligation id 走唯一
  `sha256("hctl-obligation-v1\0" + JCS(preimage))` 管线。
- CLAIM：publishing ref 作 durable pending journal；本地 `update-ref` CAS + 远端
  `--force-with-lease`；push 结果未知按 pending 是否为 remote tip 祖先恢复
  delivered/published/lost，lost 先存 recovery ref。re-claim 精确 fence 当前 claim；
  forward / environment-reset / rewrite-or-rollback 阻尼、第二次无进度 replacement
  escalated、三条 thaw 径均由链事实重放。
- VERDICT/quorum：在事件所在链位置验证 active fencing token、exact revision、PR head、
  memo source 与 base 可达性；历史上曾合法而后来被新 claim fence 的 verdict 只失去当前
  票，不误报 `CORRUPT_CHAIN`。per revision latest-wins；required quorum 只计
  COMPLETE + APPROVE + covering scope。COMPLETE verdict 开新 damping window；
  escalated 后 verdict 不构成第四条 thaw 径。
- Merge：唯一 coordinator + capacity=1；strict base/head/quorum/config 双时点检查；
  `gh pr merge --squash --match-head-commit --body-file`；封闭 receipt 字段、单 parent、
  tree equality、fact-tip prefix 与历史 config 全量 replay。合法 receipt 是 durable
  completion fact，work branch 删除后仍可关单；无 receipt/非 squash/坏 receipt 分别
  `UNRECORDED_MERGE` / `UNJUDGEABLE_MERGE` / `INVALID_RECEIPT` 红灯。
- 命令：`doctor`、`status [--json]`、`claim`、formal-default `begin`、`verdict`、
  `merge [--check]`、基础 `wait`、`trailer`、`version/help`。输出带 obligation id、
  holder、state、next action；gate 人读输出带 mode/threshold。重复 begin/claim、
  同语义 verdict、已完成 merge 都 state-aware，不重铸事实。
- build hygiene：`go.mod` 版本检查、buildinfo revision/module pin 检查；
  `enforcement=active` 与 `hctl@bootstrap` 组合硬拒。

## 2. 实现取舍

1. `source.commit` 是可审计 provenance，不进 obligation identity；只要 commit 在相应
   base/main 可达、同 path 的 blob 精确相等，即接受同一 frozen revision。不能把 loader
   当下选择的 commit OID 错当身份字段。
2. CANCEL(claim) 在 holder 自己链上按拓扑即时清 current claim；另一席链上的 CANCEL
   没有跨 ref 总序，只能在最终快照清除仍然 current 的 exact claim。取消已被 fence 的祖先
   不溯及其合法后继。
3. receipt 优先于 live branch 推导 completion；无 receipt 的旁路 squash 只能在尚有
   branch/head 证据时作级③检测，内核不猜一个普通 main commit 属于哪个已删除分支。
4. D-41 composite 当前采取最保守且可机械表达的判据：`full` 覆盖；composite 至少同时含
   非空 `fix_verification` 与 `delta` 才覆盖。schema 没有 path/surface mapping，故未伪造
   字段外的“全覆盖证明”。
5. P1 `wait` 是每次 tick 全量 reconcile 的前台叶子命令，无 daemon、poll leader、
   notify 或 auto merge。

## 4. 不由 author 擅裁的四项

### E1 — activation 与 exact buildinfo pin 必须两步

同一个 squash commit 不能在自己的内容里预先写入自己的 OID。若 P1 采用 git OID pin，
可实现且无循环的顺序是：

1. gated squash 合入 kernel，得到不可变 commit `K`；
2. 从 `K` build 二进制；
3. 后续 gated activation PR 写
   `kernel = "hctl@<K>"`、`enforcement = "active"`。

因此本 author PR 没有擅写 `.hctl/seats.toml`。把 activation 强塞进同一 squash 会制造
永远不匹配的 stale-binary；改用 semver 又与“源码入仓、每机本地 go build、无 Release”
下 buildinfo main version=`(devel)` 冲突。请 claude gate 明确认可两步 cutover，或另行修订
D-24/D-38。

### E2 — bootstrap 历史没有 P1 可重放的 audit baseline

27l 已登记 p1-corpus 无 receipt 合入；本 kernel 仍按 27j 的 bootstrap memo gates 合入，
也不会天然产生 CLAIM/VERDICT/merge receipt 链。P1 事件闭集与命令面没有
repair/baseline/cutoff 事实；伪造 receipt 会破坏 D-37。当前内核因此诚实红灯，且
activation 前必须由 coordinator 裁定一种可重放 cutover：

- 增补正式 bootstrap baseline/cutoff 规则；或
- 提前开放受约束的 forward-only repair；或
- 明确把 activation 推迟到 P2 repair 后。

“已有 memo 看起来审过”不能替代机器可重放事实。

### E3 — composite scope 缺字段级覆盖定义

现有 schema 只有 blob endpoints 与 findings 字符串，没有 assignment review surface、
path mapping 或 finding registry。实现能校验 shape、端点 OID、full/composite 组成，却
不能证明某组 endpoints 覆盖“assignment 要求的评审面”。本实现采用 §2.4 的保守最小判据；
若 spec-conformance gate 要求更强证明，须先补 schema/裁定，不应在 Go 中暗造规则。

### E4 — P1 命令表存在两个 phase 交叉

- D-43 把 `scratch / memo / trailer` 都列为 helpers；D-44 又把 scratch、memo plumbing
  明列 P2。实现按 D-44 与点火 brief，只交付 `trailer`。
- P1 事件闭集含 CANCEL，K-06 旧文也曾写 `hctl cancel`，但 D-43 的 P1 command surface
  没有 cancel，点火 brief同样未派发。实现完整 parse/marshal/derive CANCEL，但没有擅增
  CLI 动词。

两项均请 spec-conformance gate 判为 D-44 的有意 defer，或给出一个明确 follow-up
assignment。
