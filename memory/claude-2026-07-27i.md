## 1. 问答轨迹与论证

1. **「为什么 Python，不能 Rust 吗」**——审计发现：D-24 原记录论证是「Python vs shell」（round-01 字符串病），Rust 从未被正面对比，质疑成立。
2. **「cmd 工具最重要的是效率，Rust 效率最高且是二进制」**——本机实测证伪效率论：Python 启动+import 20–40ms、本地 git plumbing <10ms、**网络 ls-remote 4.1–4.7s**、纯 Python 折叠 5000 事件 14.7ms。hctl 是 I/O 编排器非计算工具，语言差异 ≈ 总墙钟 1%；最高频路径（wait）单进程跨 tick 阻塞，启动成本每次等待只付一次。效率不构成换语言理由；**二进制分发/漂移免疫构成**（tomllib 事件：本机 python3 <3.11 无 tomllib，seats.toml 严格校验被迫跳过——解释器漂移的活案例；用户补充：Python 依赖包问题是长期痛点）。
3. **「那 Go 呢？我倾向二进制分发」**——二进制既为需求，Python 头号支柱（零安装）被覆盖，对决只剩 Go vs Rust。Go 胜面：交叉编译零配置；六席 LLM 评审/维护成本接近 Python（无 lifetime 噪声，紧 token 席位友好）；秒级编译不拖两堂修补循环；**生态先例**——git-appraise（我们的 schema 先例）与 gh 均为 Go（D-20/D-21 延伸）。Rust 仅在类型严格性与 JCS crate 上小胜——本工具正确性来自语料+git 物理，非进程内不变量，不构成决胜。

## 2. D-24 amend 终态（已转录 DECISIONS）

- 实现语言 **Go**：单 module；Go 版本 pin（go.mod + doctor 检）；依赖最少、vendored + go.sum 锁定（TOML 解析库；JCS 手写 ~150 行对 corpus #28 向量锁死）。
- **分发=源码入仓、每机 `go build` 一次**（clone + build + PATH）；不入仓二进制（膨胀）、不走 Releases（多供应链+REST）；本地编译天然免 macOS quarantine。
- **stale-binary 自检（新漂移类的封法）**：二进制漂移形态从「解释器版本」变为「改了源码忘重编译」；Go buildinfo 自动嵌 `vcs.revision`，hctl 每次启动对 seats.toml kernel pin 自检，不符即拒（级②）——比解释器漂移更可防。
- 原 Python 案动因（拒 shell 字符串病、语料可回归、batch plumbing 纪律）全部继承；gate.py/coauthor.py 收编时以 Go 重写；git-appraise Go 源作实现参考。
- 上轮口头提的「P3 Rust 翻转条款」**不设**（从未入账；二进制目标已被 Go 满足，不规划第二次重写）。
- 语料体系零变化：corpus 断言 CLI 行为，语言不可见——语言改判的重写险本就被语料压最低，此为该设计的既定红利。

## 3. 排班咨询记录（用户问：写码的活可以交给 grok 么）

可以——排班是用户裁决位，能力矩阵是配置不进内核。但按用户自给能力表与 seats 声明，主笔建议：

- **codex 主写内核**（capabilities 含 implementation/spec-precision；P1 实现级规格大半出自其手——两阶段 CAS 算法、receipt 字段表、恢复态表，热上下文在彼，K-16 经济）。
- **grok 主写语料 + 对抗 gate**（corpus #1–28 半数是 grok 自己要的攻击案；tests 与 code 由不同席各写再互相 gate，结构最健康；gater≠author 法律下 codex 写内核恰好把 grok 的对抗镜头留在 gate 位——其最值钱处）。
- gates 建议：kernel ← grok（对抗）+ claude（METHOD/DECISIONS 符合度）；corpus ← codex（精密）+ claude；merge coordinator=claude（seats.toml 既定）。
- 若用户仍要 grok 写内核：可行（万金油），代价=对抗 gate 换人 + 精密修正轮次可能增加。

用户定排班后：主笔落首批两份 static assignment 文件（`.hctl/assignments/`，首次 dogfood 件）+ 两席开工 brief。

## 4. 机器前置实测（用户问：要装什么依赖库）

- **本机（mac）**：`go1.26.5 darwin/arm64` 已在位——零前置。
- 通则：机器级前置**只有 Go 工具链**；库依赖 vendored 入仓（`vendor/` + go.sum），首次 `go mod vendor` 由 scaffold 者执行一次并提交，此后全员离线 `go build`——**永不做每机装库**（这正是弃 Python 的核心动因的镜像面）。ubuntu 机若缺 Go：官方 tarball 或发行版包一条命令；doctor 检 `go version` ≥ go.mod pin。
