## 2. 核心架构优势评估

1.  **静态文字 DAG 即全部授权**：
    *   在 fire 开工前将节点、边、动作与 Gate 指派写死在 `discussion/rounds/<id>.md` 并提前合入 `main`。
    *   **DAG 即全部授权**：Worker 模型无自我授权面，消灭了认领锁与任务发明面，杜绝越权风险。
2.  **失败模式切至良性侧 (Fail-Closed on Liveness)**：
    *   节点卡死仅导致“本回合停摆等用户”（活性延迟），绝不会将未通过 Gate 的代码合入 `main`（完整性违规）。
    *   坚决执行“宁可停摆等用户，绝不跳过失败节点继续”的安全红线。
3.  **全 Git 本地信令与心跳机制 (Zero API Cost)**：
    *   使用本地 `refs/heartbeat/<harness>-<machine>` 与 `refs/round/interrupt`，通过 `git update-ref` 与 `git for-each-ref` 进行本地信令交互。
    *   **零 API 成本**：不 push 到远程 `origin`，不污染提交历史，不消耗 GitHub API 配额。
    *   **三层防线**：结合结构信号检查、心跳 SHA 静止检查 ($\ge 3$m 判死) 与节点超时分级 (60m/45m/10m 上报，90m 兜底硬中断)。
    *   **$\le 2$s 中断传播**：Watchdog 或用户更新中断 ref 后，所有睡等 Worker 在 2 秒内干净退出。
4.  **完美兼容既有治理纪律**：
    *   完全继承 Policy v4、REVIEW-PROTOCOL、纪律 3（单主笔）、纪律 13（Gate 五闸/仅审 Delta）、纪律 14（PR 终态对账）与非作者 Gate 约束。
