# Claude Memory 2026-07-26j — Harness 协作架构设计讨论（独立方法论，未裁定）

> 性质：设计讨论落档；**零施工，五个裁定点全部待用户**
> 背景：用户动机 = 协作环境清理（script/policy/guideline 满天飞），要一个独立于本项目、可独立部署的 harness 协作方法论；round-01 负面案例作反面教材

## 用户 brief 要点

- 座位：codex(gpt-5.6) / claude(fable-5) / grok(grok-4.5) / opencode(glm-5.2) / kimi(kimi-k3) / agy(gemini-3.6)。能力配对：GPT/GLM 逻辑精密件（缺全局观、偏 patch）；Fable/Kimi 愿景宏观件（nit 挂一漏万）；Grok 高效+对抗特长、万金油副手；AGY 只讨论、只写自家 memo。token：GPT/Fable/Grok 足，GLM/Kimi 紧。
- 共享 repo、各自 branch；**任一时刻一 branch 一写者**，写串行（active PR 时新 author 工作等待——pros/cons 待议）；读不受限（并行 review/gate/memo）。
- 本机为主，存在跨机接续；不用 RPC、不用 inode；git API 有 quota 要省；通知机制要 mechanical/deterministic、少 LLM。**订阅可靠性是已证明的反复出错点**（交了 PR/comment 接收方漏掉，title 不 match 等）——用户处方：宽进严出、按提交者过滤、按内容而非 title 判断。
- 协作以 PR 为原子：author 开/merge，gater 审，re-gate 循环；gater 属性待设计（阻塞性/explicit yes/P0-only/超时跳过，可组合如 A or B）。驱动两式：① predefined DAG（关系冻结，可反复 re-gate，不动态长依赖）② ad-hoc 口头指定。
- Ghostty 一 harness 一 tab；tab 内可多 sub-agent（一 build 多 review/plan）。

## Claude 设计判断（讨论稿）

1. **定性**：座位制多 harness 协调内核。业界多 agent 框架（LangGraph/AutoGen/CrewAI）进程内 + LLM 路由，违反 mechanical 要求；对口先例是人类开发工作流工具。
2. **轴心 = level-triggered**（K8s controller 教训）：通知只叫醒不携带语义；醒后跑纯函数 `derive` 重扫状态推导各座位欠账。漏醒/多醒无害。修正用户提法：「按内容理解」和「title regex」都不要——把信号结构化（writer/kind/pr/head/verdict），路由=字段匹配，零 regex 零 LLM。宽进严出：宽在醒，严在结构。
3. **事实源入 repo**：每座位一条 `refs/coop/<seat>` append-only 空树 commit 链（JSON message：VERDICT/PR_OPENED/HANDOFF/NOTE），单写者 per ref 天然无冲突；本机共享 .git 即时可见，跨机 push/fetch 同批 ref = 跨机连续性的全部。GitHub comment 降级为给人看的镜像；gh 只留 pr create/merge。**不访问 API handle comments 的答案 = 别让 comment 当事实源**。`git ls-remote` 一次调用看全 ref 含 `refs/pull/N/head`（纯 transport 无 REST）。先例：Gerrit refs/changes、git-appraise（review 入 git notes）、Radicle（issue/patch 皆 git 对象）。
4. **PR 状态机**：OPEN(H)→GATING→CHANGES_REQUESTED→GATING(H')→QUORUM_MET→MERGED，全部由 verdict 集合+head+merge 状态机械推导；**verdict 钉 head**（继承 round-01 gate.py 正确点：head 动旧 PASS 失效自动回欠账名单）。
5. **Gater 四轴代数**：阻塞性（blocking/advisory）× 判定（explicit/lazy）× 审级（full/P0-only）× 超时动作（escalate/substitute 预声明 deputy）；quorum = 小布尔表达式（AND/OR/n-of）——Gerrit submit requirements 同形。**独立意见两条**：blocking gater 禁 silent skip（沉默即同意 × 订阅曾漏 = 最危组合，超时只许 escalate/deputy）；lazy 只配 advisory 且 level-triggered 就位后才开。
6. **active-PR 等待**：pros=基线唯一/打回不连坐/免 rebase 地狱；cons=author 空转/队头阻塞/诱发攒大 PR。解法三条并用：**发布串行、起草流水线**（active PR 期间可写下一件不可开 PR——Zuul speculative pipeline 思路）；**memo 类路径白名单豁免**（round-01 实证零冲突）；**锁在 branch 不在 tab**（sub-agent 并行读与内核无关）。
7. **活性降级为 UX**（对负面案例的架构级回应）：watchdog 只报告不扣扳机；**取消全局 interrupt**——卡住 = stalled 可恢复 + dashboard 亮灯，绝不 poison 状态。心跳协议（含刚 seal 的 v1.3）在新架构整体退役——它是给「活性当权威」这个缺陷打的补丁。五事故对照：kimi 探针错目录→活性不进正确性；grok-mac-mac→工具生成 ref 名校验 id；glm 尾段判死×2→义务本身取消；漏 comment→level-triggered+结构化 verdict；判死中断全回合→无核按钮。
8. **其余**：两种驱动统一为 edge record（DAG=冻结集合，ad-hoc=口头授权单条；「DAG 即全部授权、不动态长依赖」保留）；能力矩阵是 plan 期数据不进内核；AGY 围栏 = 其 branch 只许 memo 路径（pre-push 白名单，机械）；人保持 fire 位，`wake` 只响铃打印待办，tmux 自动注入留二阶段。
9. **收敛形态**：`wake`（哨）+`derive`（推导）+`verdict`（落）三小工具 + policy 文件（edge record + gater 表达式 + deputy 链）+ dashboard；独立方法论 repo，本项目为第一采用者并删本地散件（GIT-PROTOCOL §8 配方 / ROUND-PROTOCOL 心跳三层 / watch_pr 均被收敛）。

## 追记（同日）：是否另开 repository——Claude 判定「是」

用户问「是不是该开另一个 repository 来写这个」。Claude 明确判「该开」，五条理由：

1. **Register 不同**：Abacistopia 是 CoAgNET spec 的家；此为组织 harness 干活的元工作流。混住代价已现——`fix(round)`/`feat(round)` 流量稀释 spec 演进史，三份治理文件与 spec 纪律搅同层。
2. **目标本身要求独立**：「独立部署实施」意味着他项目可采用；独立后 abacistopia 变第一采用者，删本地散件有明确迁移目标。
3. **演化节奏不同**：spec 治理重、工具需快迭代——generation-CAS 一批（control/merge/wait_round + ref transaction + 文件锁，Codex 同日落地）即例证。
4. **Dogfooding 闭环**：方法论 repo 用自己的方法论开发自己（零号采用者）。
5. **工具的家 ≠ 信号的家**：协调信号（refs/coop/*、verdict、policy 实例）永远在被协作的工作 repo（信号跟着工作走，跨机前提）；新 repo 装工具/设计/schema/采用指南。引入用 clone+PATH 或单文件安装，**不用 submodule**（多 worktree 与跨机会痛）。

配套立场：现有 `scripts/round/` **冻结不搬家**——服务当前 round 模式到新内核就绪，不再加 feature；新 repo 按 level-triggered 从零写。迁移是采用事件不是搬运事件——旧 interrupt/心跳架构正是退役对象，搬过去= 把病根带进新房。
