## 2. B 组定稿

### 2.1 B1 obligation id（定稿）

```
preimage = canonical_json({
  "assignment": {"id": "<logical-id>", "blob": "<full-blob-oid>"},   # 静态；动态: {"assign_event": "<commit-oid>"}
  "kind": "author" | "gate" | "merge",                               # P1 闭集；consult 留 P2
  "target": "<branch-slug>",                                         # P1 = assignment 的 change 身份（author.branch_slug）
  "aspect": ""                                                       # author/merge 为空；gate = "<gate-id>:<gater-seat>"
})
obligation_id = "sha256:" + hex(sha256("hctl-obligation-v1\0" + preimage))   # 全长；协议内禁截断，展示可缩
```

- **head 永不进 id**（27d 维持）；gate 类 CLAIM 记 **`revision_at_claim = {base, head}`**（codex 修正③照收——与 B2 严格 base 闭合：base 或 head 任一前进 ⇒ claim stale 回池=显式 re-claim eligibility）；author 类跟 assignment+slug 生命周期。
- 碰撞与歧义封口（grok 钉死①④ + codex 字段细节）：preimage 含 **logical id + blob OID 双料**（纯 blob 的同内容异 path 碰撞消除）；loader 拒绝项目内重复 logical id；hash 带版本与 domain separation；**事件同时保存结构化 preimage 与派生 id**（审计与诊断）。
- `aspect` 闭集（grok 钉死②）：语法按 kind 定死如上，禁自由字符串路由。
- **assignment 死后**（grok 钉死③）：CANCEL/supersede 后旧 id 的 claim/verdict 由 derive 判 dead target，写动作级②拒绝。
- **churn 风暴诚实条款**（grok 新攻击面）：assignment 文件无语义变更 ⇒ blob 变 ⇒ 全 claim 作废=合法 re-gate 风暴。处置：status 亮 `assignment_revision moved`；`.hctl/**` 变更须 required gate（§2.3）；低 churn 纪律级④点名。
- head H1→H2→H1 非漏洞（codex）：exact tuple 同则同 revision；ref 回卷由链完整性规则另报。

### 2.2 B2 base freshness + merge 串行化（重写——codex 反例成立）

27d「merge-as-obligation 即白送串行化」**撤回**：CLAIM 只互斥同一 obligation，PR-A/PR-B 两个 merge obligations 可同时 active；跨席更无 CAS 交点。定稿采 **coordinator + capacity slot**（codex 方案全收，grok 条件并入）：

1. 项目配置唯一 **`merge_coordinator = <seat>`**（bootstrap = claude；改绑走 `.hctl/**` gated PR）。
2. 所有 merge obligations 只能指派给 coordinator 席；loader 拒绝其他指派（语料必测）。
3. coordinator 席 repo 级 **`merge_capacity = 1`**。**可执行性来源**：全部 merge claim 落同一条席链 ⇒ 单 CAS 域 ⇒ capacity 谓词在同一 ref snapshot 上可判——coordinator 唯一性是承重结构，不是行政偏好。
4. **claim(kind=merge) 前置条件**（grok 条件）：derive 于同 snapshot 见 required quorum green（exact `{base, head}`）且无 active merge claim；级②拒绝抢跑。
5. 流程：claim merge slot → fetch 全事实 → exact `{base,head}` + quorum 二次 re-check → `gh pr merge --squash --match-head-commit <head> --body-file <receipt>` → fetch main → **验 squash commit 单 parent == `Hctl-Base`** → 验 receipt → receipt 关闭 merge claim。`--match-head-commit` 只护 head；base 靠前查+后验，后验不符=完整性事故（不假装事前拒绝——codex 诚实条款）。
6. **receipt 封闭字段**（不留省略号）：`Hctl-Version: 1` / `Hctl-Assignment` / `Hctl-Obligation` / `Hctl-PR` / `Hctl-Base` / `Hctl-Head` / `Hctl-Merge-Claim` / `Hctl-Method: squash` / `Hctl-Fact-Tip: <seat>=<event-tip-oid>`（可重复——钉住 quorum evaluator 当时读到的各席链 prefix，无时钟重放）。
7. 严格 base **先严后松的松弛路径版本化**（grok 条件）：P3 前禁止配置旋钮；任何放松必须走 schema_version + DECISIONS supersede，status 自描述规则代际。摩擦账（grok 估算）：k≲5 在飞 PR 时 re-gate 上界 k(k-1)/2 次、热上下文 delta 复审——dogfood 可接受。
8. 橡皮图章对策（grok）：短周转重复 APPROVE 级③审计黄灯，不入自动逻辑。
9. self-merge 澄清：merge 是 quorum green 后的机械动作，判断已在 verdict 层完成（gater≠author 法律在彼处）；coordinator 可 merge 自己 author 的 PR。
10. adopters 钉 squash；非 squash ⇒ `UNJUDGEABLE_MERGE` fail-closed。

### 2.3 B4 授权面（定稿——两堂条件全收）

- 不变量拆两条、等级各标（codex 修正⑤）：**「ASSIGN/CANCEL 确由人发起」= 级④信任前提**（`authority: {kind:"user"}` 是**声明不是证明**，任何能写链的席都能填——诚实写进信任边界，多真人/对抗 profile 才需要签名/独立账号，bootstrap 不造）；**「begin/verdict/merge 必须回溯冻结 assignment」= 级②机器拒绝**。前者的机械性永不倒灌自后者。
- **`.hctl/**` 文件变更（assignments/seats/config）必须 required gate ≥1 非 author 席、禁 silent self-merge**（grok 绕过#2 封口——事件层与静态 DAG 层同锁）。bootstrap 过渡：P1 merge wrapper 落地前维持自开自合例外，例外随 P1 交付自动终止。
- schema 补：CANCEL 精确引用 {assignment revision | obligation | claim}；同 logical id 冲突 payload ⇒ `AMBIGUOUS_ASSIGNMENT` 写动作 fail-closed；同内容 CANCEL 幂等折叠；escalate 永不隐式创建 ASSIGN。
- 其余绕过路径按 grok 表处置：伪造转录=信任边界内可伪（诚实声明+级③审计）；escalate 刷屏=status 聚合；draft 不占 claim/slot 故无占地攻击；网页 merge=C7 `UNRECORDED_MERGE`。

### 2.4 B5 fencing + HANDOFF（定稿——两堂分歧裁定）

fencing 维持 claim-OID 律：首 claim `reclaim_of=null`；re-claim 必须 `reclaim_of == 当前 active claim OID`（push CAS 定赢家）；完成类事件引用 active claim OID、derive 拒 stale 产物；「第几代」从链数、不进协议。

**HANDOFF 分歧裁定**（grok 要原子转移 / codex 要关旧+新 claim 两步）——按 CAS 域物理拆开，两堂各得其正：
- **同席跨化身**：claim 本就是**席级**资产（machine/session 只是溯源，K-26/⑫），化身切换**不需要任何协议事件**——claim 持续 active、overdue 照算；如需人读交接记录，落 NOTE（纯溯源）。release 窗口在此形态下不存在（grok 的双空窗口担忧物理消失）。
- **跨席转手**（P2 实装、P0 定状态机）：两步——from 席链 HANDOFF（关闭自身 claim、标 obligation `pending_accept` 指向目标席）→ 目标席 CLAIM 引用该 HANDOFF OID（chain of custody）。**`pending_accept` ≠ unclaimed**：他席不可抢（写动作拒绝）、目标席 attention 亮「待接」、超窗走 overdue 回池——无双空窗口（grok 担忧闭合），接收者显式认领（codex 要求保全）。

## 3. C 组定稿

### 3.1 C1 幂等（codex 修正④照收）

判据改 **ancestry**：`git merge-base --is-ancestor <pending-commit> <remote-tip>` ⇒ delivered（覆盖「push 成功后他人又 append」态）；分叉 ⇒ lost，存 recovery 后 CAS 对齐。**弃两案**：tip 等值判据（覆盖不全）、blob-OID 兜底（同 payload 异 parent 是两个合法事件，blob 只作 payload 审计——corpus 必测）。settled 后重发同语义命令由 state-aware command 返回现状（已有 active claim/同 revision 同 verdict ⇒ 不重写）；外部 RPC caller 的 idempotency key 留未来，不进 P1 事件。crash 于 commit-tree 后 update-ref 前：悬空对象可 GC、重做安全（publishing 未动）——非问题，写明即可。

### 3.2 C3 schema 命名收束（codex 条件照收）

信封定稿：`schema_version`（int）/ `type` / `actor{seat, machine, session|null}` / `created_at`（RFC3339 UTC）。**supersede 27c 采纳清单一项**：appraise 的 10 位零填充 epoch 字符串**不抄了**——那是 notes 字符串排序的 workaround，链有拓扑序；「双时戳互证」审计位保留，形态改为 created_at vs commit timestamp。`v`/`ts`/`timestamp` 三套并存就此终结。`max_severity` P1 直接省略（要则只展示）。

### 3.3 C4 → K-05 显式改写（codex 条件照收）

gate 的**内核轴收敛为三**：mode / quorum / on_timeout；**threshold 降为 review 参数**（assignment 声明、展示给 gater 的审题输入，gater 据此只选 APPROVE/REQUEST_CHANGES）。不再称四轴，避免读者期待内核按 severity 自动放行。DECISIONS 记 K-05 amends。

### 3.4 C5 三分法（重写——codex 反对成立）

「未知 type/版本跳过继续」对控制日志不安全（旧内核跳过未来 CANCEL/授权收紧后在不完整事实上 merge = silent skip 复活）。定稿三分：
1. **结构损坏**（非线性/多 parent/坏 JSON/seat 与 ref 不符）⇒ `CORRUPT_CHAIN`：整链 quarantine、相关写动作 fail-closed（grok 的「窄定义」保持）。
2. **结构合法语义不支持**（未知 type/未知 major version）⇒ `UNSUPPORTED_FACTS`：保留对象、展示已知 prefix 与未知 event OID、**相关写动作 fail-closed**、提示升级 hctl。
3. **已知非语义事件**（如 NOTE）⇒ schema 校验后可忽略正文，不影响 gate/slot。
前向兼容的正确含义=新 reader 读旧事实，**不是旧 writer 假定未来控制事实无效**。

### 3.5 C7 补记 wire form（codex 条件照收）

无结构化 receipt 的 main commit 永不自动转 recorded；operator 未给全 exact assignment/base/head/PR/claim 前保持红灯；修复 forward-only 且明确引用被补记 commit；repair attestation schema 未定前**债保持 unresolved，禁止借 NOTE 偷渡 correctness**；`hctl repair merge-receipt` 是否进事件闭集 P2 裁。

### 3.6 C9 窗口与 frozen（两堂条件合流定稿）

- **窗口** = 同一 (assignment revision, obligation_id)，自上一次 completion/CANCEL 起；**只计远端链上 accepted CLAIM**（CAS 输家不落链，天然不计）。
- **可验证进度** = 义务相关 git 事实前进（gate：目标 head 前进或 verdict 落链；author：分支 tip 前进或 memo 合入）；进度插入 ⇒ 计数降黄/重置。**纯墙钟不作进度**（心跳不复活）。
- 判色：首次 re-claim（overdue failover 的期望路径）= 黄；**第 2 次 re-claim（第 3 个 accepted CLAIM）且无插入进度 = 红 + escalated**。
- **escalated 是推导态、不是事件**（K-06 血统：无 escalate 事件类型可刷屏，grok 的 DoS 面整体消失）；席位主动上报用 NOTE（category=escalation，纯 advisory 不碰 gate/slot——与 NOTE 法律无冲突）。
- **frozen 语义**：escalated 期间 claim writer 级②拒绝新 re-claim；解冻三径全是既有动词——用户 CANCEL(claim)（义务回池、计数清零）/ CANCEL(obligation)（义务死）/ 新 ASSIGN revision（新 id）。

### 3.7 其余维持项吸收

C8 补：formal begin 的 claim 成功而 branch 操作失败 ⇒ 重跑发现同一 active author claim 并继续，**不得再铸 claim**。C6 补：本地 writer 单 parent CAS 标级②，不扩写成「server 永不可回卷」的级①。链治理（grok 遗留⑥）：P0 写明职责拆分——derive 增量读走 tip-keyed 可丢缓存、链结构校验自上次已验 tip 增量进行，缓存可丢算法不可含糊；compaction 仍不设计（无数据）。

## 5. 评审收敛纪律〔用户提出，主笔具体化——进 P0 METHOD 评审协议章〕

**问题**：逐轮评审各冒新问题 ⇒ 来回拉扯不收敛。诊断：不是评审者失职（各轮所审对象确有新增内容），是**评审范围与完整性义务从未被声明**——没有契约，轮次就没有收缩保证。

**纪律四条**：

1. **范围单调收缩，且由机械规则定义**：首轮 = 该 revision 全量；后续轮 = **fix 核验（对照上轮 findings 清单逐条销账）+ delta（两 revision 的 diff）**，仅此二者。范围不由评审者自由发挥；未变更且已封口的内容不在范围内。这是 K-04 patchset 语义在评审面的投影（27d/27e 各 memo 均钉 blob OID，delta 可机械计算）。
2. **完整性声明是 verdict 的必填结构化字段**：`scope: {kind: full | delta | fix_verification, …}` + `completeness: COMPLETE | INCOMPLETE`。COMPLETE = 「本范围内我再无保留发现」；INCOMPLETE 必须明示未覆盖面（时间/token/能力不足），**partial-silent 禁止**——K-05「required 禁 silent skip」的评审形态。**执行等级②**：derive 的 required quorum 只认 exact revision 上的 COMPLETE verdict；INCOMPLETE 不满足 gate（可见、促重派或 deputy），机器拒绝而非礼貌期望。
3. **晚期发现 = 逸出（escape），允许但例外化**：禁止晚期发现 = 带病合入（fail-open），不可取。对已封口内容的新发现必须：标 `late-finding` + 一句逸出原因（为何上轮范围内未见）；**merge 前** = 该 gater 对同 revision 出新 verdict（**per (gater, obligation, revision) latest-wins**——Gerrit 语义，此处显式立法）；**merge 后** = NOTE(category=late-finding) + 人裁决是否开修复 assignment。逸出不重启已封口范围、不自动 stale 他人 verdict。
4. **收敛保证由构造给出**：范围只会是「上轮 findings + diff」的函数，fix 若不引入新内容则第 N+1 轮范围 ⊆ 第 N 轮；配合完整性声明，轮次有限收敛。评审者的对价：给出 COMPLETE 就要背书范围内无保留，逸出会被记录归因（级③审计，非惩罚性——目的是让 COMPLETE 声明有分量）。

**即时溯及本会审**：27e 的下一轮（若有）按本契约执行，性质为**封口核验轮**，范围封闭 =（a）转录忠实性清单——两堂核对各自的阻断项/条件/钉死清单是否被 §2/§3 忠实落位（checklist，非重审）；（b）**仅审 27e 新增设计六项**：①HANDOFF 两形态裁定 ②escalated=推导态+解冻三径 ③coordinator=claude 绑定与 `.hctl/**` gate 过渡条款 ④红线=第 2 次 re-claim 的两堂计数取齐 ⑤obligation preimage 具体形态 ⑥本节评审纪律。（c）verdict 必须带完整性声明。此外无内容在范围内；A/B/C 已同意项非经逸出程序不得重开。
