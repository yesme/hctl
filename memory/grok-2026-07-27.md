## 0. 总判（先给结论）

**可立，不可原样进 P1 实现。**

底稿把「多真相源 / 心跳义务 / 评论事实源」三条历史病根砍干净，level-triggered + 三层承载 + 叶子命令模型是正确骨架。补遗把永续双 fire 从「边界事故」改成「常态」，并用 CLAIM 吃掉跨机互斥——方向对，**但 CLAIM 目前是命名优雅的半规格**：mutex 物理可用，obligation 身份、租约语义、链治理、震荡阻尼四项未钉死。这四项不定，P1 一写就会在语料里发明方言。

**一句话攻击摘要**：

| 面 | 致命度 | 一句话 |
|---|---|---|
| 三层承载 | 高（运维/考古） | 层间非原子 + coop 无服务端护栏 → 静默假空集与不可恢复删链 |
| slot | 中高 | 跨机双 begin 窗口未闭合；与 CLAIM 统一心智后边界更糊 |
| CLAIM（⑪） | **高（补遗新核）** | 链膨胀 / re-claim 震荡 / obligation id 粒度三洞全开 |
| wake | 中 | 六席双驻班下 ls-remote 礼貌性与假唤醒成本未量化 |
| 执行等级 | 高（方法论自指） | 多条新纪律仍停在级 4；与 K-17「无执行方案=设计债」自相矛盾 |
| 化身模型 | 中 | 语义正确；session 字段与租约进度缺执行面 |

**会审角色建议给用户的综合权重**：主笔方案 **采用骨架、冻结 CLAIM 语义再写 schema**；不要在 CLAIM id/租约未定前开 P1 写动作。

## 1. 专题攻击

### 1.1 三层承载（K-01）失效模式

设计意图：事件 / 叙事 / 变更三层分家，GitHub 页面零义务，git repo 可考古。攻击点不在「分三层错了」，在 **层间契约的可执行性** 与 **事件层的耐久假设**。

**F1. refs/coop 未 fetch → 假空集（静默错误）**  
derive 的输入是「我看见的 git 事实」。消费仓漏配 `fetch = +refs/coop/*:refs/coop/*` 时，本地 coop 为空或陈旧：status 报告「无欠账 / 无 claim」，驻班者空转或重复开活。  
- 级 2 可防：`doctor` 硬失败（缺 refspec / 远端有链本地无 / 时钟落后 N 小时）。  
- **缺口**：doctor 非每次 derive 必跑；wake 循环内若只 `ls-remote` 远端 tip 而本地未 fetch 对象，可能「看见 tip 变了但读不到 payload」。必须规定：**wake/status 的事实读取路径 = fetch（或 ls-remote+按需 fetch）后的对象**，禁止「只比 tip SHA 假装 reconcile」。  
- 漏醒无害（K-02）**不等于**「看见空集无害」——空集是**错误观测**，不是 level-triggered 的合法状态。建议：观测完整性校验失败时 exit 非 0，且输出「不可判定」而非「无义务」。

**F2. coop 链被 force-push / 删除 → 考古灭绝**  
append-only 在 free 私有仓 **不是级 1**（无 ref 保护、单账号可删）。  
- 误删 / 错误 `push --force` / 工具 bug 重写 tip → 整席事件史蒸发。  
- memo 与 PR 仍在，但 VERDICT↔memo 指针、CLAIM 时序、HANDOFF 链断裂 → derive 只能从 PR/分支残余**降级猜测**，与「事件层是协调真相」矛盾。  
- **要求**：METHOD 失败行为章必须写 (a) 备份策略（mirror fetch / 第二 remote 只收 coop）；(b) 检测 tip 非 ff 时 **拒绝静默快进**，status 红灯「coop history rewrite detected」；(c) 恢复=人工从 mirror 或 memo 考古重建，forward-only。不要假装 append-only 是物理定律。

**F3. 顺序纪律「先合 memo 后落 VERDICT」**  
这是跨层两阶段提交：memo PR merge（变更层+叙事层）与 coop append（事件层）**无法原子**。  
- 只合 memo 未 CLAIM/VERDICT → 叙事在、协调不知「已交卷」（咨询模式可接受；gate 模式变成「人以为审了、系统未记账」）。  
- 只落 VERDICT 未合 memo → `memo:` 悬空或指向任务分支临时 SHA；main 考古断链。  
- 级 2 补丁：`hctl verdict` **硬依赖** memo 指针已在 `origin/main`（或允许 `memo:` 钉 blob SHA 且 blob 必达——更强）；否则拒绝。级 4 的「记得先合」不算执行方案。

**F4. 叙事层 opaque 与「过程不丢」的缝**  
K-10 内核对 memo 零解析是对的（防 LLM 路由回归）。但「过程考虑不丢」全靠人写流水账——**无结构保证**。对抗结论：这是产品诚实问题不是内核 bug；METHOD 应写明 **可机械保证的是事件+PR 状态，memo 质量是排班/closeout 义务（级 4，点名）**，别让用户以为三层=过程自动永存。

**F5. 变更层与事件层 head 漂移**  
K-04 钉 head：head 动 → 旧 VERDICT stale。好。缺口：  
- squash merge 后任务分支删除，事件仍钉 pre-merge head——历史正确，但「对 main 的 gate 语义」要靠 merge 检出（见⑤）。  
- force-push 任务分支（作者误操作）→ 一串 VERDICT 集体 stale + CLAIM 仍可能指向旧 obligation：需 define「head 变迁时 claim 是否自动作废」。

**总评 K-01**：层拆正确；**必须补「观测完整性」「coop 非 ff 检测」「verdict→memo 可达性硬门」** 三条失败行为，否则三层在故障时退化为「本地幻觉」。

### 1.2 slot / 与 CLAIM 的统一心智

底稿 slot：发布闸门，`pr create` 时刻查 slot。补遗：slot=author 义务的认领形态。优雅，但 **统一后边界案例更需要 id 与窗口定义**（见⑪）。

**S1. 跨机双 begin 未 push（未决项 6，未闭合）**  
两化身同时 `begin` 同 slug 或争同一 author 名额：本地分支都建得出，slot 若只查本地/陈旧远端 → 双绿。先 push 分支者赢，后者 non-ff 或 PR 撞车。  
- 这与 CLAIM 的 push-mutex **同形**，应 **同一套「先登记后干活」**：author 路径也是 `claim(author, obligation) → 再 begin/pr create`，而不是「pr create 碰巧当 claim」。  
- 若 slot 只在 `pr create` 查、begin 不登记，则「双 begin 长时间起草」窗口仍在——与「写锁在发布不在思考」一致，但 **双 PR 撞 slot** 必须级 2 拒绝第二个 create，且 status 显示谁持有。

**S2. hosted 并发分支**  
`branch_patterns` 含 `grok/*` 类 provider 名：derive 从分支名推 PR 归属省 OPEN 事件——好。风险：provider 分支名 **不含稳定 slug** 时 obligation id 难钉；同一 seat 两 hosted session 两分支，slot 计数如何与 CLAIM 对齐要写死。

**S3. memo 微分支与 slot**  
memo 不占 slot、即合——正确。攻击：席位用 memo 分支偷运「准 author 大改」绕 slot。  
- 级 2：memo 路径围栏 + 体量/路径审计（级 3）可挡「重提交」；挡不了「把设计写进 memo 当事实」——那是知识升格纪律（K-10），级 4 点名即可。  
- 不要为防偷运把 memo 重新绑进 slot（会杀死咨询模式）。

**S4. slot 与 CLAIM 双 mutex 异质**  
- CLAIM mutex = git push 单 ref 原子。  
- slot/`pr create` mutex = GitHub PR 存在性 + 本地 derive。  
两套原子域。**把 slot「心智上」说成 claim 可以，实现上必须承认：author 认领若只靠 pr create，则「已 claim 未 create」状态不存在；若引入 CLAIM 事件覆盖 author，则 pr create 前已有可见持有者——更优。** 对抗建议：**P0 明文规定 author/gate/merge 三类义务共用 CLAIM 事件，slot 仅是 author 类在 derive 中的投影（并发度计数），不再是平行原语。**

### 1.3 CLAIM 攻击面（⑪，重点）

K-28 正确抓住了「永续双 fire + 单席单链 → push 即锁」。以下三洞是补遗到可实现规格的距离。

#### 11a. 链膨胀

**机制**：每次 claim / re-claim /（可能）release 都 append；双化身永续驻班 + 多义务 → 高频小 commit 灌进 `refs/coop/<seat>`。六席 × 两机 × 每义务数次 claim → 月级即可「协调史 >> 代码史」。

**为何有害**：  
1. 每次 derive 若 naive 全链扫描 → CPU/IO 随时间坏掉（与「每次调用全量 reconcile」叠加）。  
2. fetch 变重；clone 配 refspec 的新机器首拉痛苦。  
3. 与「小 JSON 事件」初衷对冲——事件变小但 **次数爆炸** 等价变大。

**不充分的借口**：「git 很能扛」。能扛不等于 derive 要 O(n) 永久。

**对抗要求的治理（选一写进 METHOD，P0 定口径）**：  
- **G1 快照+增量（推荐）**：链上允许 `CHECKPOINT`/`SNAPSHOT` 类事件或独立 `refs/coop/<seat>/snap`，derive 从最近可验证快照 + 其后 delta 重建；旧段保留考古、默认不扫。  
- **G2 逻辑折叠**：同一 `obligation_id` 只保留最新 CLAIM 为 live，历史仍 append 但 index 旁路（`.git/hctl/` 可丢缓存可重建）——缓存可丢，**索引算法不可含糊**。  
- **G3 硬限额**：单日 claim 次数 / 链深度 doctor 黄灯——只观测不够，需配合 G1/G2。  
- **禁止**：靠「人工 gc force-push」——与 F2 考古灭绝同构。

CLAIM 事件是否必每次干活都写？若「claim 后无进度也可续命」会诱使心跳式 re-claim → 膨胀加速。见 11b。

#### 11b. re-claim 震荡

**场景**：  
1. mac claim 义务 O，`started_at=T0`。  
2. 窗口 W 到，ubuntu derive 见 overdue → re-claim 成功，开工。  
3. mac 从休眠回来，未 fetch 或基于旧缓存，也走 re-claim；或 mac 认为自己仍在干、发进度 NOTE 同时 ubuntu 已 verdict——交叉。  
4. 更糟：**双方对称 standby**，均配置相近 W，O 在 overdue 边界被踢皮球（A claim → 近 W 时挂起 → B re-claim → A 稍后 re-claim…）——**活锁式震荡**，verdict 迟迟不落，链上全是 CLAIM。

**根因**：只有 `started_at` + 固定超窗 + 显式 re-claim，**没有**：  
- 租约世代（epoch / generation）；  
- re-claim 冷却与优先级（例如原 holder 在 grace 内可续，challenger 必须等 grace）；  
- 进度续租信号（非心跳进程，而是 **可 verify 的产出事件**：NOTE 含 progress、分支 tip 前进、memo 合入）——「无产出」必须可判定，不能只靠墙钟；  
- 反对称：standby_delay（补遗可选）若 **默认关闭且双机都当主力**，震荡是设计常态不是边角。

**对抗要求**：  
1. **CLAIM 记录 `epoch` 单调整数**；re-claim 必须 `prev_epoch` 匹配 live，否则拒绝（防脑裂双活）。  
2. **状态机显式**：`unclaimed → claimed → (released|overdue|satisfied)`；satisfied 由 VERDICT/merge 推导，不靠再写 claim。  
3. **续租 ≠ 心跳**：允许 `CLAIM` 的 `touch` 仅当 derive 看见 **义务相关 git 事实前进**（目标 PR head 变、memo 指针出现、scratch 不计入）。纯时间续租 = 心跳义务复活，违反 K-06。  
4. **re-claim 阻尼**：overdue 后首次 re-claim 立即；同一 obligation 在 τ 内第 n 次 re-claim 要指数退避或人工 escalate（黄灯升级红灯）。τ 与 W 分开配。  
5. **双主力对称配置标为反模式**：METHOD 写「一席多化身应有主/备或不同 standby_delay」；doctor 可检测「两机近同时 claim 频率异常」。

**死机回收**补遗方向对；**假死（慢思考 / 长 context）** 与真死不可区分——这是分布式租约古典难题。诚实写法：W 按义务类型分档（gate 复审短、author 大任务长），并允许 holder 用 **可验证进度** 拉长，而不是 LLM 自觉续租。

#### 11c. obligation id 粒度

**这是 CLAIM 能否实现的第一阻塞。** 补遗说「池子里的活」「先到先认领」，未定义活的主键。

候选与攻击：

| id 方案 | 过粗 | 过细 | 其他病 |
|---|---|---|---|
| 整席 attention set | 一席同时只能干一件；杀并行 | — | 废 |
| PR number | author 尚未开 PR 时无 id；咨询无 PR | 一 PR 多 gate 无法分认领 | merge 后 PR 号仍在、语义变 |
| 分支名 `work/seat/slug` | 同分支多义务（多 gater）抢一把锁 | — | handoff 换执行者不换名——好；但 gate 义务绑 author 分支略扭 |
| edge_id + role | 需 edge 稳定 id | 可能偏细 | ad-hoc EDGE 事件要自带 id |
| (kind, target, head_sha) | head 一动 id 变 → claim 全作废（或许可） | 过短命 | 与 K-04 一致但 re-claim 噪声大 |
| 全局单调 obligation 序号 | — | — | 要权威发号器；与「无中心」张力 |

**对抗立场（建议主笔采纳的可实现口径）**：

```
obligation_id = hash(kind, target_key, aspect)   # 稳定、不含 head、不含 machine
live 判定另附 expected_head 或由 derive 现算 head
```

- `kind ∈ {author, gate, merge, consult}`（闭集可扩，但须 schema）。  
- `target_key`：author/consult = 任务 slug（或 memo 话题 id）；gate/merge = PR number **或** 分支名（P0 钉死一种，禁止混用）。  
- `aspect`：gate 时 = gater seat 或 gate label（防两 gater 抢同一 PR 的同一把锁——**应允许并行**，故 aspect 必含 gater 身份）；author 时 = 空或 `slot`。  
- **head 不进 id**：claim payload 记 `head_at_claim`；derive 若 `current_head != head_at_claim` 且 kind=gate → claim **自动 stale 回池**（与 VERDICT 钉 head 同构），holder 需 re-claim 新 head。这避免「锁死在旧 patchset」。  
- author 长任务 head 狂进：**不应**因 head 变丢 claim——故 stale 规则 **按 kind 分岔**（gate 跟 head，author 跟 slug 生命周期）。

**粒度法律**（建议升格，类似 K-05）：  
1. 一 claim 同一时刻只能被一个 (seat, avatar) live 持有。  
2. 不同 aspect 的 gate 可并行 claim。  
3. 禁止「claim 整个 repo」或「claim 所有 overdue」。  
4. id 必须 **可从 git 事实 derive 重算**（无侧车发号）；若用 PR number，零 REST 路径必须已能稳定得号（见⑤）。

**未定义则必炸的场景**：同 PR 两 required gater；author claim 与 gate claim 交错；cancel 边后 claim 残留；consult 无 PR 无分支仅 memo。

#### 11d. 其余 CLAIM 失效（简列）

- **本地 CAS 成功、push 失败**：必须 rollback 本地 tip 或立即 re-fetch 重置；否则同机多 tab 以为持锁。语料必测。  
- **CLAIM 后 EDGE 被 CANCEL**：holder 仍干活；derive 应显示 claim 目标已死，写动作拒绝。  
- **provenance machine/session 可伪造**：信任边界内可接受（K-17），但审计靠它则级 3 记日志即可，**不可**当鉴权。  
- **与 HANDOFF 关系**：补遗说已认领只能 HANDOFF 或 overdue re-claim。需规定 HANDOFF 是否自动产生「对端 CLAIM」还是对端再 claim——双写易抖，建议 **HANDOFF 事件原子转移 live holder**（一代 epoch+1，from/to），避免 release+claim 两洞窗口。

**⑪ 总判**：CLAIM 可作核心机制，**条件是 P0 先钉 obligation id + 租约状态机 + 链上索引/快照策略**；否则不要进 P1 写动作。现有「push 即 mutex」只解决了互斥的传输层，没解决分布式锁的 **对象、租期、死锁、活锁**。

### 1.4 wake

**W1. 经济学（对应④）**  
假设：30s `ls-remote`，六席双机双驻班 = 12 个等待循环。若每循环一次 ls-remote：24 次/分钟级。Git 托管软限额与「礼貌」通常扛得住小型私有仓，但：  
- 与 CI、gh、其他 fetch 叠加未建模；  
- 全员宽进：任意 ref 抖 → 12 处被踢醒进 derive，**假相关唤醒**成本是 CPU/token（驻班 LLM 若每次 wake 退出都 digests 输出）。  

**建议**：  
- 规范写清：**默认间隔可配、下限保底**（防 2s 回归 kimi 病）；  
- derive 相关性过滤后，**无本地义务变更则 wake 继续睡**，输出勿逼 LLM 重读全文；  
- 同机多 seat 共享 wake 守护进程 **不**回归常驻服务——保持「有人 wait 才有轮询」；可在文档中允许 **同机 fetch 合并**（一 fetch 多 seat status）作为实现优化，非架构变更。

**W2. 假醒与 token**  
自描述输出好（K-13/K-22），但若每 30s 无变化也刷「无变化」进上下文 → 驻班 session 膨胀。要求：无变化时 **静默继续**（进程不退出）；仅变化或 timeout 才把摘要打到 stdout 给 LLM。这是实现细节，但影响 K-16 经济学，P2 规格应写死。

**W3. 监听面正确**  
ref 平面 vs 文件系统——同意，且是对 worktree 误解的良药。无新攻击；保持。

### 1.5 执行等级（K-17）漏防

原则「违规是设计问题」「无执行方案=设计债」——用这把刀砍补遗自身：

| 纪律 | 当前 implicit 级 | 漏防场景 | 应落到 |
|---|---|---|---|
| 先 CLAIM 后干活 | 4 | 直接改代码/pr create | 2：写动作包装命令查 live claim |
| 先 memo 后 VERDICT | 4 | 悬空 memo: | 2：verdict 校验 main 可达 |
| 无边不动作 | 4 | 驻班 LLM 自造任务 | 2：begin/merge/verdict 查 edges |
| 不抢非 overdue claim | 4 | 恶意/bug force re-claim | 2：epoch 校验；3：审计 |
| append-only coop | 伪 1 | force push | 3 检测非 ff + 备份；无法 1 |
| slug 不带化身 | 4 | 人起名 `foo-mac` | 2：begin 校验字符集/后缀黑名单 |
| trailer 证据 | 2（规划） | 无会话证据乱填 | 2：trailer 拒写 |

### 1.6 化身模型（K-26…K-29）失效模式

**语义**：seat=脑子，machine=椅子，quorum 按席——**同意，且应用补遗的 quorum 论证收束**。攻击在执行与边界。

**A1. session 字段（⑫）**  
各 harness session id：不稳定、不可读、或「本目录最近会话」模糊。  
- 放入事件 provenance 若缺失 → 同机多 tab 不可分。  
- 对抗建议：`session` **降为 best-effort**；同机多 tab 互斥 **真依赖 update-ref CAS（级 1）**，不依赖 session 字符串。实测清单记「能否提供」但不阻塞 P1。

**A2. 模型漂移同席**  
seats.toml 写死 model= grok-4.5；他日换模型仍同席 → 考古「谁的意见」靠 trailer 不靠 seat。ok。但 **能力矩阵当调度输入** 时，换模型不换 seat 会误派——那是排班问题，METHOD 一句即可。

**A3. 双驻班正确性 vs 成本**  
补遗：正确性无害。对抗：**正确性在 CLAIM 完备后无害；成本（token 双倍抢活）有害**。主备或 standby_delay 应升为 **推荐配置默认**，不是深埋可选。

**A4. 椅子名牌 vs 任务名牌**  
K-29 正确。级 2 黑名单后缀 `-mac/-ubuntu/-b` 于 **slug**；worktree 目录自由。doctor 可扫远端分支名违规。

**A5. 化身与 HANDOFF**  
跨机接活：A 落 HANDOFF，B 未在线 → 义务应回何态？若仍 displayed as claimed by A until overdue，则 W 要覆盖「人已口头交棒但 B 未 claim」。建议 HANDOFF 进入 `pending_accept` 或直接转移 holder 到 B（B 未 ack 前 B 的 status 亮「待接」）。未写则实战靠 overdue 凑合——可活但丑。

## 2. 审题清单逐条表态（①–⑭）

> 格式：**判**（通过 / 有条件通过 / 打回补规格）+ 攻击要点 + 要求动作。

### ① 三层承载失效模式
**有条件通过。**  
见 §1.1 F1–F5。必须补：观测完整性（不可判定≠空集）、coop 非 ff 红灯、verdict 的 memo 可达性硬门、coop 备份/恢复叙事。derive 在「层间中间态」的行为要写进失败行为章，禁止静默当无事。

### ② notes vs 裸 ref 链
**倾向裸 ref 链（或每席一条替代 ref），notes 作否决项除非证明 CLAIM 友好。**  
攻击 notes：  
- notes merge 语义与「单 tip 链 + CAS push」心智不完全同构；多 notes 扇出/折叠易诱使「非单写者」误用。  
- CLAIM 需要的是 **有序 log + 原子 tip 更新**；裸 commit 链最直。  
- git-appraise 先例在 review 锚定，不在分布式 claim 锁。  
P1 前通读 appraise **同意作为义务**；选型判据应显式加入：**是否便于 epoch CAS 与 checkpoint**。不要为「verdict 挂在 commit 上好看」牺牲 CLAIM 主路径。

### ③ slot 边界案例
**打回补规格（与⑪合并闭合）。**  
跨机双 begin、hosted 并发、memo 交互见 §1.2。验收：语料至少五案——双 begin 同 slug、双 pr create 抢 slot、hosted 名分支占 slot、memo 并行 author、claim 后不 create 的超时回收。

### ④ wake 经济学
**有条件通过。**  
30s 固定可接受为默认；六席双驻班要有 **量级说明 + 同机 fetch 合并优化许可 + 无变化静默**。不对 GitHub「礼貌」装死——写预期 QPS 与退避（429/二次限流时 wake 拉长间隔）。

### ⑤ derive 可判定性（零 REST 闭环）
**有条件通过，P1 最高风险项之一。**  
merged 检出靠 squash `(#N)` + 分支消失：  
- 非 squash / rebase merge 策略一变就瞎；  
- 手工 merge 无编号；  
- 分支删了但 PR 未 merge（关 PR）→ 假阴性/假阳性。  
**要求**：消费仓 **钉死 merge 策略=squash**（adopters 文档级 2 说明）；derive 对「不可判定 merged」显式 unknown，**required gate 不得把 unknown 当通过**。quorum 只读 coop VERDICT——这条干净。PR number 作 obligation id 的前提是 number 可得：开 PR 后才有 gate id，author 前期用 slug——与⑪一致。
