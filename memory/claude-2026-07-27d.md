## 2. B 组：真分叉，逐条建议

### B1 obligation id 代数

- **分叉**：grok ⑪c——稳定键 `hash(kind, target_key, aspect)`，head 不进 id，按 kind 分岔 stale ↔ codex ⑥-B——assignment-revision 锚定，gate id 含 `{base, head}`（head 动=新义务）。
- **建议（合流案）**：`obligation_id = hash(assignment_revision, kind, target_key, aspect)`。
  - `assignment_revision`：静态 = main 上该 assignment 的 **blob OID**（`{commit, path, blob}` 钉死，codex 锚定，防 fire 后原地变义——codex ⑩-14）；动态 = ASSIGN event commit OID。
  - **head 永不进 id**；gate 类 CLAIM 带 `head_at_claim`，`current_head ≠ head_at_claim` ⇒ derive 判 claim stale 回池（grok 分岔规则）；author 类跟 slug 生命周期，不因 head 前进丢 claim。
- **理由**：安全性由 K-04 freshness 法律独立保证（verdict 钉 `{base,head}`，B2），id 含不含 head 不改安全性只改代数。稳定 id 使同一义务的 claim/handoff/escalate 史天然聚合，status/cancel 有单一句柄；head 进 id 则每 push 铸新义务，链噪声与 re-claim 次数放大（grok ⑪c 已指出）。codex 的两条核心诉求全保留：revision 锚定（assignment 变 ⇒ 新 id ⇒ 旧 claim 死）、旧 verdict 不可复用（由 B2 exact match 保证）。
- **代价明示**：derive 按 kind 实现两套 stale 规则（gate 跟 head、author 跟 slug），语料各覆盖。

### B2 base freshness + merge 串行化

- **分叉**：codex ⑤——P1 严格 `{base, head}` 全匹配 + 串行化四选一必选其一 ↔ 底稿 K-04 只钉 head；grok 未表态 base。
- **建议**：
  1. required gate 的 verdict 必须 **exact `{base, head}`** 匹配 merge 前快照（codex 严格案照收）；
  2. 串行化选 **merge-as-obligation**：merge 义务是普通 obligation、走 CLAIM 互斥——即 codex 四选一中 coordinator 案的零新原语形态，串行化由 CLAIM 机制白送；
  3. `hctl merge` 流程：claim merge obligation → fetch 后全量 derive re-check → `gh pr merge --squash --match-head-commit <head>` + 结构化 trailer body（`Hctl-PR/Hctl-Base/Hctl-Head/Hctl-Claim/...`）→ fetch main 验 receipt；
  4. base advance 放松（tracking-base 等）**P3 语料实测后再议**，先严后松、不开旋钮（K-05「旋钮最少化」）。
- **理由**：严格规则是唯一零判断规则（K-17 级②可执行）；一 seat 一 slot 下在飞 PR 少，merge train 串行摩擦有限；re-gate 是 delta 复审吃热上下文（K-15），边际成本低。merge queue 免费私仓不可用；全局 merge CAS 是与 claim 重复的新原语，弃。
- **代价明示**：每次 main 前进，其余在飞 required verdict 全部 stale——**吞吐换确定性**。此为日常摩擦度定档条款，请两堂特别掂量（§5）。

### B3 EDGE→ASSIGN 改名 + memo 分支独立 namespace

- **分叉**：codex ⑥-B/③——「edge」名实不符（无 from/to，实为带 author/gates/merge 的工作项）；`work/<seat>/*` 混装 author 与 memo，「memo 不占 slot」机器不可判 ↔ 现状 K-07/K-08。
- **建议**：两条全接。`edge.schema.json` → `assignment.schema.json`；`.hctl/edges/` → `.hctl/assignments/`；事件 EDGE → ASSIGN。分支双 namespace：`work/<seat>/<slug>`（author-class）、`memo/<seat>/<slug>`（memo lane）；seats.toml 分列两组 pattern，doctor 查跨席跨 lane 两两不相交。
- **理由**：K-20 naming policy 是自家法律——assignment 是业界词，边不是我们造的对象；分道后「memo 永不占 slot」从纪律（级④）升为结构（级①），derive 从分支名判 lane 零歧义。
- **代价明示**：改 K-07/K-08 词汇与 AGENTS.md 写规则；本仓 bootstrap 期已用 `work/claude/memo-*` 数次——旧分支名留史不改（forward-only），新约定自裁决日起用。

### B4 派工/取消授权面

- **分叉**：codex ⑩-12——任一席可向自家链写 ASSIGN ≠ 有权给别席派工，authority 未定义。
- **建议**：bootstrap 授权表三行：
  1. **ASSIGN/CANCEL：人发起**，任一席转录（payload 带 `authorized_by: user`，转录席只是记录员）；
  2. **escalate 是席位唯一自主出口**（发现意外一律上报，不自造义务）；
  3. 其余写动作必须回溯到冻结 assignment 或人的 ASSIGN——「无边不动作」的执行等级落法：begin/verdict/merge 写动作查 assignment 存在性（级②拒绝）。
- **理由**：与 K-19「人=排班/点火/裁决」同构；单人类账号信任模型下不需要席间授权代数（多真人账号问题明写不在当前信任边界，grok 额外发现 1 同向）。

### B5 fencing 机制

- **分叉**：grok ⑪——CLAIM 记单调 `epoch` 整数，re-claim 须 `prev_epoch` 匹配 ↔ codex ⑪-C——claim event OID 作 fencing token。
- **建议**：**claim-OID 案**。完成类事件（VERDICT/HANDOFF）必须引用 active claim OID；re-claim 必须引用被取代的 claim OID（`reclaim_of`）；derive 拒绝 stale-claim 产物。不设 epoch 字段——链拓扑序即世代，展示层「第几代」从链数。
- **理由**：无发号器、无计数器状态，CAS 由链 parent 结构白送（K-17 级①）；grok 的防脑裂诉求由「引用当前 active claim OID、引用错即拒绝」等价实现——epoch 匹配与 OID 匹配同构，后者少一个可漂移的整数。

## 3. C 组：具体处置建议（原「授权主笔」项，一并开放两堂挑错）

- **C1 幂等身份**：**不设 `event_id` UUID**（否决 codex ⑥-C 该字段）。两阶段 CAS 的 pending commit 即幂等 token：publishing ref ≠ tracking ref ⇒ 有未决发布 ⇒ 只允许重推该 commit（对象不重造、OID 稳定）；push 结果未知时 re-fetch 看远端 tip 是否即 pending commit。blob-OID 查重作兜底。覆盖 codex ⑪-B 五个中间态（§5 请 codex 复核此声明）。
- **C2 ref 命名**：publishing 维持 `refs/coop/<seat>`（K-01 既定）；tracking 走 `refs/hctl/remotes/<remote>/coop/<seat>`（工具命名空间，明示非权威，codex ① 方向照收）。tracking 更新无 force——远端回卷 ⇒ fetch 失败 ⇒ 红灯；恢复显式走完整性流程（先存 recovery ref）。
- **C3 三 schema**：seats 按 codex ⑥-A（`write_scope`、结构化 `features`、`author_concurrency` 只收 0/1、删 `memo_prefix` 改由 seat id 派生、pattern 只许单 `*`）；assignment 按 codex ⑥-B 骨架（P1 只开 `kind=change`）；event 用 envelope + `oneOf` 判别联合、`additionalProperties: false`、只收全长 OID。quorum AST 只开 `seat / all_of / any_of / at_least` 四节点，loader 拒绝跨字段错误（codex 清单照收）。
- **C4 threshold 语义**：threshold 是**展示给 gater 的裁量参数**；内核只读 `decision`（APPROVE / REQUEST_CHANGES），永不用 `max_severity` 覆写（codex ⑥-C 案照收——LLM 只做选择题的直接应用）。
- **C5 宽进严出两分法**：结构坏（非线性/多 parent/坏 JSON/payload seat 与 ref 不符）= **quarantine 整链**、写动作 fail-closed；语义未知（新 type/新版本）= **跳过继续**（前向兼容）。调和 K-03 与 codex ① 的 quarantine 要求。
- **C6 执行等级表**：grok §1.5 与 codex ⑦ 两表合并收编；如实降级两处——hooks = 级③（可 `--no-verify`，不冒充服务端法律）、append-only = 伪①改「级③检测 + 备份」；级④仅留 memo 质量与知识上迁两条，点名配 closeout 兜底（K-16/K-17）。
- **C7 失败行为章**：`INCOMPLETE_FACTS` ≠ 空集——读动作报「不可判定」、写动作 fail-closed（两堂 F1/① 一致）；coop 回卷 ⇒ 本地 tip 先存 recovery ref 再红灯，不自动跟随不自动重建（codex ①）；备份 = 消费仓可选第二 remote（adopters 文档项）；绕过 hctl 的网页 merge ⇒ `UNRECORDED_MERGE` 审计债，补记不猜（codex ⑤）。
- **C8 命令面**：增 `hctl claim`；`begin` 默认 formal（内嵌 claim，`--draft-only` 逃生门，codex ⑧ 偏好照收）；`run` 移出内核进 adapters（消解 K-13「不驱动 harness」张力）；**`wake` 改名 `hctl wait`**（K-20 有业界词不自造；P2 未实现，改名零成本；help 文案 "block until attention set changes or timeout"）。
- **C9 阻尼与 standby**：**永不自动 re-claim**（codex ⑪-D 照收）；阻尼做成**展示+升级**而非内核退避——同一义务窗口内第 ≥2 次 re-claim ⇒ status 红灯 + escalate（grok ⑪b 的指数退避降档为观测，内核保持机械简单）；adopters 模板出厂即非对称 standby 示例，METHOD 把双主力对称配置标为反模式（grok A3 采纳为「推荐默认」，但留在经济层不入正确性法律）。
