## 1. Findings

### codex-corpus-retro#P1-01 — runner 不证明 #1–28 完整存在，缺案或 SKIP 仍返回成功

位置：`tests/corpus/run.sh:33-49`。

runner 只 glob 当前存在的文件，最终只在 `fail != 0` 时失败；它没有冻结预期 case manifest，
也不把 gate 模式下的 SKIP 当作未覆盖。因此“所有被发现的脚本没失败”被误写成了
“assignment 要求的全部语料已通过”。

可复现反例：

1. 在临时副本移走 `cases/28-jcs-vectors.sh`；
2. 运行同一 `run.sh`；
3. 得到 `SUMMARY pass=29 fail=0 skip=0`，退出码仍为 0。

同理，任意 case 退出 77 也不影响最终退出码。对普通本地探索，允许 SKIP 可以保留；但
D-05 required 禁 silent skip、D-41 required quorum 要求覆盖评审面，门禁执行必须有严格
模式：核对 #01–#28 与两项 concurrency 的精确 manifest，missing/duplicate/unexpected
case 失败，required wire case 的 SKIP 失败。否则删掉最难的一案反而更绿。

### codex-corpus-retro#P1-02 — `HCTL` 接线是空钩子，30/30 没有验证内核

位置：

- `tests/corpus/lib/common.sh:22-35`
- `tests/corpus/cases/09-begin-retry-reuse-claim.sh:34-37`
- `tests/corpus/README.md:19-35`
- `tests/corpus/BACKLOG.md:3-6`

`corpus_require_hctl` 从未被任何 case 调用；#09 检出 `HCTL` 后只执行 `:`。全套也没有一个
`Mode: hctl-wire` 案。实测把可执行的 P1 binary 传入，并强制
`CORPUS_REQUIRE_HCTL=1`。甚至把“内核”换成只会返回 0 的 `/usr/bin/true`，结果仍绿：

```text
HCTL=/usr/bin/true CORPUS_REQUIRE_HCTL=1 bash tests/corpus/run.sh
SUMMARY pass=30 fail=0 skip=0
```

结果与完全不传 binary 逐字相同。更根本地，#3、#8、#9、#12–#15、#17–#19、#24、#27
等案在脚本内现场定义一个“正确实现”，随后断言该函数返回自己刚写死的值；它们是可运行的
规格示例，不是对交付物的回归。

并行起草时先落 pure/hybrid oracle 本身合理；阻断点是 assignment/README 明写 quorum
应在 kernel 落地接线后才绿，而 PR #25 在这一步之前就被合入。27m 已进一步裁定：
pure predicate 可保留为差分 oracle，但 normative authority 是 Go 内核。最小修复不是把
所有 git 物理案重写成 Go 测试，而是：

1. 对 loader/doctor/derive/writer/merge-wrapper 等确有 CLI 可观测面的 backlog 案补真实
   `hctl` 调用与正反断言；
2. pure predicate 明标 differential oracle，不能独自代表 kernel PASS；
3. strict runner 证明所需 wire 集合非空、全执行、零 SKIP。

### codex-corpus-retro#P1-03 — 差分 oracle 对结构坏输入 fail-open，且实现 PR 弱化了冻结向量

位置：

- `tests/corpus/lib/jcs.py:71-84`
- `tests/corpus/lib/obligation.py:28-36`
- `tests/corpus/lib/derive_rules.py:119-136`
- `tests/corpus/cases/28-jcs-vectors.sh:35-50`
- `tests/corpus/BACKLOG.md:39`

D-33/D-39 与 `schema/event.schema.json` 要求：duplicate key、lone surrogate、非 I-JSON、
缺字段/坏 shape 都是结构损坏，必须 `CORRUPT_CHAIN` 或拒收。当前 oracle 有三组相反行为：

```text
parse_i_json('"\\ud800"')                                      -> ACCEPT
three_way_event({"schema_version":1,"type":"CLAIM"}, ...)     -> OK
obligation_id({"assignment":{"assign_event":OID,"extra":"x"},
               "kind":"author","target":"demo","aspect":null}) -> ACCEPT
```

第二例缺 actor、created_at、obligation 等必填字段；第三例违反
`additionalProperties:false`。这会让独立 oracle 与 schema/Go normative implementation
在安全边界上系统分叉。

而且冻结 base 的 BACKLOG #28 明列 “NFC/NFD 靠 grammar 拒、dup key/lone surrogate
拒”；本 PR 在同一次实现变更里把清单改成只剩“非 ASCII grammar、dup key”，脚本也确实
漏掉 lone-surrogate 向量。author 可以标注暂未实现，不能在交付 diff 内静默缩小验收规格。

最小修复：恢复冻结 #28 向量；`parse_i_json` 显式拒绝 lone surrogate/非 I-JSON；
obligation 校验所有 union 分支的精确 key set；three-way 分类只在完整 shape/schema 校验
成功后才把未知 type/version 分到 `UNSUPPORTED_FACTS`，其余结构坏一律
`CORRUPT_CHAIN`。

### codex-corpus-retro#P1-04 — #7 用无效 receipt 冒充合法重放，只 grep 字段存在

位置：`tests/corpus/cases/07-receipt-fact-tips-parent.sh:17-38`。

#7 的题面是“多 `Hctl-Fact-Tip` 重放 quorum；main parent == `Hctl-Base`”。当前 fixture
却把 `Hctl-Obligation` 写成 `sha256:deadbeef`，把 head、merge claim、fact tips 写成
`abc/def/aaa...`；这些都不是 D-33/D-37/D-42 所需的全长 OID。脚本随后只检查：

- commit parent 等于 base；
- Base 文本存在；
- Fact-Tip 行数为 3，且含 claude/codex。

它既不检查封闭字段集与全长 OID，也不验证 grok tip，更没有从三个 prefix 实际 replay
verdict/quorum。于是一个规范上必拒的 receipt 被标成 PASS，而“重放 quorum”这一半题目
从未执行。

最小修复：用真实 event-chain commits 形成全长 fact tips 和合法 obligation/claim/head，
验证封闭字段集、重复/缺失/未知字段、单 parent/tree equality，并从各 tip 的历史 prefix
重放出 required quorum；另设截断 OID、错 seat tip、tip 不可达、receipt/config mismatch
的拒绝向量。纯 Git fixture 可以保留，但最终还需由实际 receipt validator 跑同一向量。

### codex-corpus-retro#P2-01 — branch-pattern oracle 会把合法不相交模式误报 overlap

位置：`tests/corpus/lib/derive_rules.py:139-197`。

单星 refspec 允许 suffix；当前启发式只要两模式 prefix 兼容，很多 suffix 互斥情形也返回
overlap。例如：

```text
patterns_disjoint(["refs/heads/*a", "refs/heads/*b"]) -> false
```

不存在同时以 `a` 和 `b` 结尾的 ref，因此应为 true。该问题是 fail-closed 的可用性误报，
不放过冲突，故列 P2。修复可用单星语言的 prefix/suffix 精确相容判定；或把 schema 收紧为
canonical trailing-`*`，同时删去 oracle 的虚假通用性。

### codex-corpus-retro#P2-02 — generator 与权威 cases 已漂移，缺少 round-trip check

位置：`tests/corpus/lib/gen_cases.py`、`tests/corpus/cases/04-push-ancestry-delivered.sh:25`。

author memo 声明 `cases/*.sh` 为权威、generator 仅维护用；但重新生成会删除 #04 的一行
注释，已经不是 clean round trip。行为目前不变，列 P2。要么删 generator 避免双源，要么
在 runner/CI 增 `generate → diff --exit-code`，确保它确实能再生权威文件。
