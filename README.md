# hctl — a seat-based multi-harness orchestration kernel

**让多家 AI 各坐一席，在同一个 git 仓库里像一支工程团队那样协作。**

有作者，有评审，有对抗性的把关，有排队合并的纪律；有分工、有交接、有问责、有考古。人不再逐条转述消息、盯着每个回合——人只做三件事：**排班、点火、裁决**。

## 为什么

单个 AI 助手有天花板：一颗脑子，一种偏科，一次上下文。把多家模型拉进同一个项目，天花板就变成了新问题——谁写、谁审、谁说了算、状态存在哪、两个 agent 同时动手怎么办。市面上的答案几乎都是「再架一层服务」：进程编排器（orchestrator）、消息总线、状态数据库、常驻 daemon。每一层都是新的单点、新的漂移源、新的要人伺候的东西。

hctl 的出发点是一个观察：**协作需要的物理层，git 已经给全了。**

- 需要不可伪造的事实？——commit 与 ref。
- 需要互斥锁？——同一条 ref 的 compare-and-swap push，先到先得，后到者响亮失败。
- 需要审计与考古？——append-only 的链上历史，clone 即得全部。
- 需要跨机器同步？——push / fetch，三十年工业级传输。

所以 hctl 不是一个平台，而是一个 **orchestration kernel（协作编排内核）**：席位制、多 harness、千行级**叶子命令**，把 git 原语组装成协作语义——席位、认领、判定、法定人数、收据。它编排的是 **git 事实与义务**，不是 agent 进程：不开服务、不驻后台、不驱动 harness、不碰数据库；无人等待时，系统里没有任何东西在跑。

## 核心概念

- **席位（seat）**：一个 harness × 一个模型 = 一颗脑子一张席。机器只是椅子——同一席位可以从多把椅子上工作，投票永远按席计。
- **三层承载**：协调事实走 per-seat 事件链（`refs/coop/<seat>`）；评审全文与设计讨论走 memo lane（`memory/`，微 PR 即合）；变更本体走任务分支与 PR。GitHub 只当 merge 机器，页面零义务——**可考古的是 git 仓库，不是网页**。
- **Level-triggered**：通知只负责唤醒，状态永远是从 git 事实推导出来的纯函数。漏掉一次唤醒无害，下一次调用全量对账。没有心跳义务，没有 watchdog——「还活着吗」不是协议问题。
- **认领（claim）**：一切义务先认领后动手。同席多化身抢同一件活？一条链上的 CAS push 天然仲裁。谁在干、干了多久、换过几手，链上全有——**椅子可以贴名牌，任务不能贴名牌**。
- **判定（verdict）钉死版本**：评审意见永远绑定精确的 `{base, head}`。代码动了，旧的批准自动作废——没有「大概还算数」。
- **法定人数（quorum）与收据（receipt）**：required gate 永不静默跳过；merge 是 quorum 变绿之后的机械动作，由唯一的 coordinator 串行执行，收据写进 main 的 commit 里，事后任何人可以无时钟重放「当时看到了什么」。

## 设计法度（摘）

- **违规是设计问题，不是品行问题。** 每条规则标注执行等级：结构上不可能 > 机器拒绝 > 机器审计 > 依赖自觉。依赖自觉的条目必须少到点名。
- **LLM 只做选择题。** 哈希、日期、分支名、PR 号全部由工具生成；模型只提供语义输入。
- **宁停摆，不带病合入。** 事实不完整时读操作报「不可判定」，写操作直接拒绝——空集和「没看见」是两回事。
- **有业界词就不自造。** quorum 来自 Gerrit，reconcile 来自 Kubernetes，fencing token 来自分布式锁的教科书——预训练语料里的词是白拿的 few-shot。
- **session 是 cache，memory 是数据库。** 知识按金字塔上迁：门面 → 台账 → 结论 → 规范 → 考古；派工带指针，不带语料。

设计定稿由三个席位共同完成——claude 主笔起草，codex 与 grok 各自独立评审：一席专攻规格与实现的精密性，一席专职对抗性地寻找失效模式。五轮收敛（全量 → 六条 → 三条 → 零条），每轮 verdict 都带完整性声明。`memory/` 里那几十篇 memo 不是文档，是**这套协作方式的第一份完整现场记录**——包括它的失误：主笔亲手完成过一次绕过 gate 的错误合并，事故实录与机械化封堵方案同样在案。方法论的可信度不来自它从不出错，而来自**每个错误都变成一条可执行的护栏**。

## 不是什么

不是 **process orchestrator**（不开窗口、不驱动 harness、不常驻 daemon）——与「orchestration kernel」不矛盾：前者是进程编排服务，后者是 git 事实上的协作语义内核。不是 CI（不跑构建）；不是平台（无服务端、无账号体系）；不防恶意（护栏防失误与漂移；信任模型是单人类操作者）。它只做一件事：**把多席位协作的物理层钉进 git，让判断力只花在判断上。**
